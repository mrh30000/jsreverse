### js分析

在滑动完成后，会请求【cap\_union\_new\_verify】接口，其中有5个比较长的参数，看起来可能会有加密的，分别如下。

| 参数名 | 来源 |
| --- | --- |
| ua |  |
| sess |  |
| collect |  |
| eks |  |
| vData |  |

那现在js看看这些参数是怎么来的，ua看名字很有可能是User-Agent的简写，把值直接放到base64解码，可以发现就是与请求的User-Agent一模一样。

sess 从【cap\_union\_prehandle】的请求返回的，而这个请求并没有其他的加密请求参数，那么sess就可以理解为是由服务器返回的。

接着直接搜索【collect】

![](https://attach.52pojie.cn/forum/202410/11/163258xvb3wwlrbu2uir39.png)

发现只有两处，实际就是下面的js中

![](https://attach.52pojie.cn/forum/202410/11/163300q33tvtttv8tzwwkt.png)

【collect】就是由【C()】得到，同时也带出了下面的【eks】参数由【R()】得到·，非常好。一次找到两个。

最后是vData，发现在下面的函数出现到，那么接下来动态调试看看。

![](https://attach.52pojie.cn/forum/202410/11/163302gphydxg76gvzx77x.png)

可以看到C函数绑定的是getData函数，继续往里面走

![](https://attach.52pojie.cn/forum/202410/11/163304yb88933v63fff13t.png)

里面调用的是g的函数，而这个已经是vmp的函数了，就不往下走了，接着很容易发现R函数绑定的是getEks函数，并且也会走到vmp内部

![](https://attach.52pojie.cn/forum/202410/11/163306ybopvpkkbti58lbn.png)

接着再往下，去到send下断点

![](https://attach.52pojie.cn/forum/202410/11/163308l5dxuk8i5izlouo5.png)

发现send的时候，还没有vData参数，但是实际发出去的时候却有了，那么很有可能和某音一样重写了XMLHttpRequest的原型，那么查看一下是否被修改

![](https://attach.52pojie.cn/forum/202410/11/163310k8zl6c66lff8eoc9.png)

发现确实被重写，同时也是指向了vmp的内部，那么现在总结一下参数的来源

| 参数名 | 来源 |
| --- | --- |
| ua | User-Agent的base64编码 |
| sess | 前面请求返回 |
| collect | getData  (jsvmp-tdc) |
| eks | getEks  (jsvmp-tdc) |
| vData | XMLHttpRequest.prototype.send  (jsvmp-slide) |

### 初步分析vmp结构

把tdc的js下载到本地，然后格式化阅读一下。

![](https://attach.52pojie.cn/forum/202410/11/163312xq5vire9ylbqlbl9.png)

里面有一大段base64编码的字符串，以及一个大数组，这两个最终会解码成一个大数组，这个大数组就是包含字节码的数组，并传入【\_\_TENCENT\_CHAOS\_VM】运行

![](https://attach.52pojie.cn/forum/202410/11/163314cizne4csy9v2zsds.png)

经过一段分析，发现主要用到的是前四个参数

![](https://attach.52pojie.cn/forum/202410/11/163316dvi75iuo5ylvzljk.png)

配合上面的一个子函数创建的指令，大概可以猜测到各个参数含义

| 参数 | 作用 |
| --- | --- |
| 1 | pc寄存器 |
| 2 | 字节码数组 |
| 3 | 函数调用者 |
| 4 | 调用堆栈 |
