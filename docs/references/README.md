### 二、新坑 55：版块翻到末页「回卷第 1 页」，不是返回空

`animation`/`安全工具区`/`教学培训区` 三个版块实际只有 8~60 页，
但旧脚本只在「返回**空**列表」时熔断 —— 而 Discuz 超页后会**返回第 1 页内容的复制**，
于是 `安全工具区` 白抓 **142 页**（p9~p150 全是同一条 `thread-1859777`）。
**修复**＝`board-sweep.py` 增加「**连续 2 页零新增 ID**」熔断（进度行现在打印 `(+新增数)`）：

```python
added = sum(1 for x in d if tid_of(x["url"]) not in rows)
stale = stale + 1 if added == 0 else 0
if stale >= 2: break        # 已到末页，站点回卷第 1 页
```

⇒ 判「翻到底」的判据是**新增数归零**，不是「返回空」。`Thread --page N` 同理。

### 三、新坑 56（本轮最重要的修复）：已归档 ID 正则会**吃掉首位数字**

历轮（含 skill 的 `jsrev-scan.py`）用 `^[a-z0-9]*-?(\d{5,})-?.*\.md$` 提取已归档帖子 ID。
问题出在 `[a-z0-9]*` —— **它包含数字**，贪婪匹配会把文件名开头的数字一起吃掉：

| 文件名 | 错误结果 | 正确结果 |
| --- | --- | --- |
| `2080428-shortvideo-sig3-fingerprint-pure-algo.md` | `80428` | `2080428` |
| `2066191-websocket-reverse-rebuild-html.md` | `66191` | `2066191` |

⇒ **全部 51 个早期 `<id>-<slug>.md` 文件的 ID 提取都是错的**，已归档集合因此漏掉 **49 个 ID**；
后果是这些老帖会被重复抓取、重复归档（`52pojie-2080428-*.md` 与 `2080428-*.md` 并存）。

**本轮实测影响面**：256 条候选里 **32 条其实是已归档老帖**（`2082553` 某御验证码、`2123850` 某 q 音乐
jsvmp、`2106217` iv8、`2066191` WebSocket… 全是历轮已归档的「名帖」，所以命中表每轮都把它们捞回来）。

**修复**＝文中第一个长度 ≥5 的数字串即帖子 ID：

```python
m = re.search(r"(\d{5,})", f)     # ✅ 正确
# m = re.match(r"^[a-z0-9]*-?(\d{5,})-?.*\.md$", f)   # ❌ 会吃掉首位数字
```

⚠️ **同时修正历轮 README 的计数**：第二十轮 README 写的「唯一帖子 ID 852」正是这个错误正则的产物，
**实际当时是 827**；本轮修正后为 **854**（827 + 本轮 27）。此后各轮计数应以新正则为准。

### 四、口径：候选三层门禁（本轮第一版失败过一次）

`build_probe21.py` 第一版把「裸 `插件`/`扩展`/`小程序`」当成 web 逆向信号 →
