## 逆向某 AI 编程工具仓库快照加密：从 app.asar 到本地解密 tar.gz.enc 全记录

### 0x00 前言

昨天看到某公司出品的 AI 编程工具有私自上传用户数据的新闻。本着"我的数据我做主"的精神，决定把它的加密方案扒出来，并且不依赖官方私钥，自己动手完成解包。

最终效果：**本地生成一对 RSA 密钥，让 \*\*\* 用我们的公钥加密快照并"上传"到本地 mock 服务器，再用私钥完整解密出一个 292MB 的工作区快照（2801 个文件，SHA-256 校验通过）**。

仅供学习研究。

### 0x01 目标定位：加密逻辑藏在哪

\*\*\* 是典型的 Electron 应用，安装目录下能看到标准布局：

```
D:\Software\***\
├── ***.exe
├── resources\
│   ├── app.asar          ← 主逻辑都在这
│   ├── ***\***.cjs       ←  bundled CLI 运行时（11MB）
│   └── ...
```

用户数据目录 `C:\Users\<user>\.***\v2\checkpoints\<workspaceHash>\pending\` 下能找到目标文件，每个密文旁边还有一个同名 `.envelope.json`：

```
{
  "schema": "repo_snapshot_encrypted_artifact/v2",
  "contentAlgorithm": "aes-256-ctr",
  "keyWrapAlgorithm": "rsa-oaep-sha256",
  "keyId": "1",
  "nonceEncoding": "ciphertext-prefix-16-byte",
  "aadEncoding": "canonical-json-v1",
  "aad": { "workspaceKeyHash": "f47a8fb36d2c", "kind": "baseline", "compression": "tar.gz" },
  "encryptedDataKey": "CjKgdXWN4cCqh9mkcG7szDxY...(base64)",
  "plaintextSha256": "c50601ed1667794672017318715a4fa9..."
}
```

Envelope 已经把算法自报家门了：**AES-256-CTR 加密内容 + RSA-OAEP-SHA256 封装密钥**。但魔鬼在细节里（IV 怎么放、密钥怎么派生），还得看代码。

### 0x02 静态分析：解包 asar 找加密函数

Electron 的 asar 就是个打包格式，一行命令解开：

```
npx @electron/asar extract app.asar out/
```

加密逻辑在 `out/host/index.js`（约 2.5MB 的 esbuild bundle）。搜 `tar.gz.enc` 和 `encryptedDataKey` 很快定位到核心函数 `encryptArchive`（混淆后名为 `oct`）：

```
async function oct(e){
  // ...
  let t = v_e(32),          // randomBytes(32) —— AES 数据密钥
      r = v_e(16);          // randomBytes(16) —— IV
  let o = await S_e(e.plaintextArchivePath),           // 明文 tar.gz 的 sha256
      n = Xst("aes-256-ctr", t, r),                    // createCipheriv
      i = ect(e.encryptedArtifactPath);                // 创建密文输出流
  await rct(i, r);                                     // 先把 16 字节 IV 写进文件头
  await nct(b_e(e.plaintextArchivePath), n, i);        // 流式加密写入
  let s = { ...e.envelopeInput,
    encryptedDataKey: Qst({                            // publicEncrypt
      key: e.uploadKey.publicKeySpkiPem,
      padding: Jst.RSA_PKCS1_OAEP_PADDING,
      oaepHash: "sha256"
    }, t).toString("base64"),
    plaintextSha256: o };
  await df(e.envelopePath, s);                         // 写 envelope.json
}
```

结合文件头部的 import：

```
import { constants as Jst, createCipheriv as Xst, publicEncrypt as Qst, randomBytes as v_e } from "crypto"
```

**加密规范（也就是该仓库快照的加密规范）就此完全确定**：

| 项 | 值 |
| --- | --- |
| 内容加密 | AES-256-CTR，32 字节随机数据密钥 |
| 文件格式 | `16 字节 IV 前缀 + 密文`（CTR 模式下这 16 字节是完整初始计数器块） |
| 密钥封装 | RSA-OAEP-SHA256，公钥来自服务器，信封里存 base64 |
| 完整性 | envelope 的 `plaintextSha256` 存明文 tar.gz 的 SHA-256 |
| AAD | 只是元数据（AES-CTR 无 AAD 概念，不参与加密） |

### 0x03 关键突破口：公钥是服务器下发的

继续追 `uploadKey.publicKeySpkiPem` 的来源，发现它来自一个 HTTP 接口：

```
qve = Wn(process.env, "/api/v1/snapshot/upload-credential");
// ...
function Vlt(e){ let t = new URL(qve); t.searchParams.set("workspace_id", e); return t.toString() }
```

服务器响应里的 `encryption.public_key` 就是加密用的公钥。再看响应校验函数 `vIe`，要求的字段一目了然：`callback.{url,body,content_type}`、`oss.{host,path,policy,x_oss_signature,...}`、`encryption.{algorithm,key_version,public_key}`、`snapshot.snapshot_id`，外层包 `{code:0, data:{...}}`。

而 `Wn(process.env, ...)` 这个构造器继续追下去，在 chunk 里发现：

```
// 环境变量可以覆盖 API 源！
envBaseOrigin: ge(e,"***_BASE_URL") ?? ge(e,"***_ENDPOINT_ORIGIN") ?? ...
// 默认生产环境源
var io = "https://***.***.***", dC = "https://***.***.***";
```

**这意味着：用 `***_BASE_URL=http://127.0.0.1:PORT` 环境变量就能把 \*\*\* 的所有 API 请求指到本地。** 而客户端对 `upload-credential` 响应**没有任何签名校验**——这就是注入我们自己公钥的通道。

再看加密触发时机：`captureBeforePromptUnsafe` —— 每次发送 prompt 前自动抓取仓库快照。加密完成后 multipart POST 到 `oss.host`（表单里 `file` 字段是密文，`callback` 字段是 base64 编码的回调 JSON，其中 `callbackBody` 带着替换好的 `encrypted_aes_key` 和 `checksum`）。

### 0x04 动手：mock 服务器 + 密钥注入

思路清晰了，四步走：

**① 本地生成 RSA-2048 密钥对**（pycryptodome）：

```
from Crypto.PublicKey import RSA
key = RSA.generate(2048)
open('private.pem','w').write(key.export_key(format='PEM').decode())
open('public.pem','w').write(key.public_key().export_key(format='PEM').decode())
```

**② 写个 mock 服务器**，核心路由：

* `GET /api/v1/snapshot/upload-credential` → 返回 `{code:0, data:{encryption:{algorithm:"RSA-OAEP-256", key_version:1, public_key:<我们的公钥>}, snapshot:{snapshot_id:"local-lab-snapshot-1"}, oss:{host:"http://127.0.0.1:18765/oss/upload", path:..., policy:..., ...}, callback:{url:..., body:"...&encrypted_aes_key=${encrypted_aes_key}", content_type:...}}}`（注意公钥 PEM 里的换行要转成字面 `\n`，客户端会自己转回来）
* `POST /oss/upload` → 把 multipart 原文落盘（**第一次没存内容，白跑了一个 292MB 的包，血泪教训**）
* 其他请求 → 透明代理到官方服务器，保证登录态和其他功能正常

**③ 带环境变量启动 \*\*\***：

```
***_BASE_URL=http://127.0.0.1:18765 ./***.exe
```

注意 Windows 下 `http.server` 默认开 `SO_REUSEADDR`，**两个进程能同时绑同一个端口**（幽灵服务器抢连接，排查了半天"Empty reply from server"），重启前务必确认旧进程已杀干净。

**④ 在 \*\*\* 里随便发一条消息**，`captureBeforePrompt` 触发：加密 → 写 pending → 上传到我们手里。

### 0x05 解密：私钥还原明文

从保存的 multipart 里解析出 `file`（密文）和 `callback`（base64 解码后 `callbackBody` 里有 `encrypted_aes_key` 和 `checksum=sha256:...`），重建 envelope，然后解密：

```
from Crypto.Cipher import AES, PKCS1_OAEP
from Crypto.Hash import SHA256
from Crypto.PublicKey import RSA
import base64, hashlib

priv = RSA.import_key(open('private.pem','rb').read())
data_key = PKCS1_OAEP.new(priv, hashAlgo=SHA256).decrypt(base64.b64decode(envelope['encryptedDataKey']))

blob = open('xxx.tar.gz.enc','rb').read()
iv, ct = blob[:16], blob[16:]

# 注意坑：Node createCipheriv 的 IV 是完整 16 字节初始计数器，
# pycryptodome 的 CTR 默认 nonce 最长 15 字节，必须 nonce=b'' + initial_value=整数
plain = AES.new(data_key, AES.MODE_CTR, nonce=b'', initial_value=int.from_bytes(iv,'big')).decrypt(ct)

assert hashlib.sha256(plain).hexdigest() == envelope['plaintextSha256']  # 校验通过
```

之后 gunzip + untar 即可。另外一个版本坑：Python 3.12 之前的 `tarfile.extractall()` 没有 `filter` 参数。
