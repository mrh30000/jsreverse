## 用 AI 辅助逆向某red书 mnsv2 签名算法：纯计算 vs 补环境

### 背景

某red书 Web 端的请求签名（x-s、x-s-common、x-t）依赖一个 VMP（虚拟机保护）加密的 JS 文件来生成 mnsv2 签名。传统做法是"补环境"——在 Node.js 中模拟浏览器环境（window、document、navigator 等），让 VMP 代码直接跑起来。但这种方式维护成本高、依赖重、容易被检测。

本次尝试的目标是：**用 AI 辅助逆向 VMP 字节码，将 mnsv2 核心算法提取为纯 Python 实现，彻底摆脱 Node.js 依赖。**

### 最终成果

整个签名链路已实现纯 Python：

* `mnsv2.py`：XXTEA 加密 + 自定义 Base64 编码，核心算法约 250 行
* `xhs_sign.py`：生成 x-s、x-t、x-s-common，调用 mnsv2.py，零 Node.js 依赖
* 经端到端验证，Python 输出与 VMP 原始输出逐字节一致

### 纯计算方案 vs 补环境方案

| 维度 | 补环境 | 纯计算 |
| --- | --- | --- |
| 依赖 | Node.js + 模拟 DOM/BOM | 纯 Python，零外部依赖 |
| 性能 | subprocess 调用开销大 | 原生 Python 函数调用 |
| 维护 | VMP 更新后需重新补环境 | 只需更新常量（key、alphabet） |
| 可移植性 | 绑定 Node.js 运行时 | 任何 Python 环境直接运行 |
| 理解深度 | 黑盒，不理解算法本质 | 完全理解每一步计算逻辑 |

### AI 辅助逆向的过程与踩坑

#### 正确的做法

1. **运行时 Hook 优先于静态分析。** VMP 字节码经过混淆，静态阅读极易误判常量。正确做法是先 Hook 关键函数（XXTEA、Base64），捕获实际的输入输出，再反推参数。
2. **逐组件验证。** 将算法拆分为独立环节（payload 构造 → XXTEA 加密 → Base64 编码），每一步都用 Node.js VMP 的真实数据做对照，确认一致后再进入下一步。
3. **用大量样本交叉验证。** 例如 Base64 字母表的提取：通过 200 次调用，收集加密后的字节与输出字符的映射关系，统计推导出完整的 65 字符字母表。

#### 踩过的坑

1. **XXTEA 密钥搞错了。** AI 在静态分析 VMP 时，把一个无关的 ASCII 字符串 `"exnsonixyangluo"` 当成了密钥。实际密钥是 `"e6483ca2a1eed5e3"`——一个看起来像 hex 的字符串，藏在函数引用旁边。**教训：混淆代码中的字符串不能想当然，必须运行时抓取确认。**
2. **Base64 字母表搞错了。** 同样是静态分析给出了错误的字母表。最终通过经验性方法（喂入已知密文、观察输出字符）才得到正确结果。**教训：对于自定义编码表，统计归纳比静态阅读更可靠。**
3. **错误定位不够高效。** 当端到端结果不匹配时，应该立即二分定位（先比较加密输入是否一致、再比较密钥、再比较输出），而不是反复审查已经正确的算法逻辑。

#### 如何用 AI 少走弯路

* **明确告诉 AI "先 Hook 验证，再写代码"。** 不要让 AI 一上来就根据静态分析写完整实现，而是先让它写 Hook 脚本，捕获运行时数据。
* **给 AI 提供对照数据。** 每完成一个模块，立即提供 Node.js 的真实输出让 AI 比对，发现偏差马上修正。
* **拆分任务粒度。** 不要一次性让 AI "把整个 VMP 逆向成 Python"，而是分步：先提取 XXTEA、再提取 Base64、再提取 payload 结构，逐个击破。
* **对 AI 的静态分析结论保持怀疑。** 混淆代码是 AI 的弱项，它容易"看到一个像答案的东西就当成答案"。运行时数据才是 ground truth。

### 核心算法简述

```
mnsv2(url, md5_1, md5_2):
  1. 构造 89 字节 payload（magic + 随机数 + 时间戳 + URL长度 + XOR编码的MD5 + 指纹 + ...）
  2. 转为 uint32 LE 数组，末尾追加原始字节长度
  3. XXTEA 加密（key = "e6483ca2a1eed5e3" 的 ASCII 字节，DELTA = 0x3C6EF373）
  4. 自定义 Base64 编码（65字符字母表）
  5. 返回 "mns0201_" + base64 结果
```

整个过程是纯数学计算，不依赖任何浏览器环境。
