## 52ZXW视频下载及链接分析过程

### 视频下载

#### 壹

首先打开播放链接`http://www.52zxw.com/course_733.html`,F12抓下包，发现并没有视频流的包，唯一有用的是 `http://www.52zxw.com/CuSunV2set_dx2.php?FlvID=0&ListID=0`，里面的内容像是播放器的配置文件。

![](https://attach.52pojie.cn/forum/201903/30/204002u2v0nm94smtmaqt4.png)

#### 贰

考虑并非是HTTP协议的播放方式，在刚刚抓到的配置文件中JcScpServer参数似乎也印证了这一点，使用的是RTMP协议。我们拿RTMPDumpHelper抓抓看，运行后使用IE访问播放页面，同时运行的rtmpsuck里抓到了当前rtmp流请求的参数

```
Streaming on rtmp://0.0.0.0:1935
WARNING: Trying different position for client digest!
Processing connect
app: vod
flashVer: WIN 31,0,0,108
swfUrl: http://www.52zxw.com/player.swf
tcUrl: rtmp://103.26.77.198/vod
pageUrl: http://www.52zxw.com/course_735.html
Playpath: word_2010_sp_/1-1.avi.asc
Saving as: 1-1.avi.asc
WARNING: ignoring too small audio packet: size: 0
```

之后就可以使用rtmpdump来下载这个视频了，为了使用方便，其中一部分参数是不需要带的，整理出来的调用方式如下

```
rtmpdump -r "rtmp://www.52zxw.com/vod" -y "word_2010_sp_/1-1.avi.asc" -o "output.flv" -s "http://www.52zxw.com/player.swf"
```

其中，`word_2010_sp_/1-1.avi.asc`是播放地址，`output.flv`是要保存的文件名，`rtmp://www.52zxw.com/vod`是之前配置文件中的JcScpServer参数

下载不难，但每次抓视频链接未免有些太麻烦了，下面我们来看看这个地址是怎么来的

### 链接解析

#### 壹

使用F12找到flash播放器的参数

```
JcScpVideoPath=MJjHb9Rgf5ge4zCDEGXLtEIfwNaC/cG2NNzUuvcIopU=&JcScpFile=CuSunV2set_dx2.php&JcScpImg=Images2/startPic.jpg&JcScpSharetitle=我爱自学网
```

JcScpFile是配置文件的链接，JcScpImg是前置图片的链接，JcScpSharetitle看名称是分享的标题，这些都没啥用。

第一个JcScpVideoPath参数应该就是加密后的播放链接。

#### 贰

把播放器下载下来，使用JPEXS Free Flash Decompiler打开，发现函数名都被混淆了。在设置中打开自动重命名标识，然后重启工具。

起先搜索`JcScpVideoPath`发现得到的结果太多，眼花。

不过`MJjHb9Rgf5ge4zCDEGXLtEIfwNaC/cG2NNzUuvcIopU=`这个值看起来像是base64编码后的文本，我们来搜下base64
![](https://attach.52pojie.cn/forum/201903/30/200329g5ll9199zcmnql11.png)

只有package2\_class2一个结果，进去看看。method\_37和35分别是base64的编解码过程，怎么区分呢。看红框输出部分，有从编码表里获取值的肯定就是编码，method\_37就是解码。

搜索下method\_37

我们找到了关键代码

```
var _loc5_:* = class_2.method_37(var_95);                                //base64解码
var_107.method_47(_loc5_);                                                                //猜测为解密函数
var _loc6_:String = convertByteArrayToString(_loc5_);        //字节集转换到文本
JcScpVideoPath = encodeURI(decodeURIComponent(_loc6_));        //处理下
```

当前文件内查找下`var_107`这个类，在文件上方找到了key和IV的来源

```
str2 = "52zxwcom";
key = new ByteArray();
key.writeUTFBytes(str2);
var_16 = new ByteArray();
var_16.writeUTFBytes(str2);
des = new class_23(key);
var_107 = new class_41(des);
var_107.IV = var_16;
```

可以知道key和iv均为`52zxwcom`，加密方式可能是des

看下var\_107的定义位置，`public var var_107:class_41;`，进入class\_41，有个函数比较显眼

```
public var var_107:class_41;

public function toString() : String
{
return key.toString() + "-cbc";
}
```

看样子加密方式已经出来了，DES-cbc,key和iv是52zxwcom，我们用易语言写个小程序测试下

```
.版本 2
.支持库 e2ee
.支持库 spec

.子程序 __启动窗口_创建完毕
.局部变量 加解密对象, 加解密对象
.局部变量 output, 字节集

加解密对象.解密数据 (#算法_DES_CBC, Base64解码 (“MJjHb9Rgf5ge4zCDEGXLtEIfwNaC/cG2NNzUuvcIopU=”, ), 到字节集 (“52zxwcom”), output, #填充方式_PKCS5, 到字节集 (“52zxwcom”), )
调试输出 (到文本 (output))
```

输出结果

```
* “word_2010_sp_/1-1.avi.asc”
```

### 总结

至此，分析完成，52zxw的加密方式并不难，比较适合新手练习

填充方式PKCS5其实是从百度搜getIV4d找到的相关源码里来的

这个网站文件名都是类似的，可以通过第一个视频的链接推导出后面全部视频的链接，包括只能VIP看的视频，全站视频随意下载。网站的安全意识未免有些差。
