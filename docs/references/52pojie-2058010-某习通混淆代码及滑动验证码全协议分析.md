今天我们分析一下这个站的登录。按常规先抓包。

![](https://attach.52pojie.cn/forum/202509/04/201232lg6rriqmrgkzb44z.png)

可以看到点击登录后有滑动验证码。
因此我们需要先分析滑动验证码。
抓包可以看到发送了五个可疑参数。

![](https://attach.52pojie.cn/forum/202509/04/201300uhq4ypbmb2r442cn.png)

然后返回了滑动的底图，缺口，以及一个token

![](https://attach.52pojie.cn/forum/202509/04/201322xxf5av3v3mj925yi.png)

通过搜索，captchaId这个参数是在login.min.js?t=20240708这个js中写死的。我们固定即可。\_是个时间戳。
那么我们只需要看chptchKey,token,iv即可。查看栈，可以看到有两个可疑的函数

![](https://attach.52pojie.cn/forum/202509/04/201338qp781h6p162awhbh.png)

我们点进去，可以看到代码里面有赋值操作。但是代码都混淆了。

![](https://attach.52pojie.cn/forum/202509/04/201353czwws7w2d7r78sks.png)

虽然混淆了，但是别慌。我们先下断点。

![](https://attach.52pojie.cn/forum/202509/04/201411ze9cg9svosy99sez.png)

我们在相同的地方打上三个断点，刷新。
可以看到'captchaKey': \_0x422ded;\_0x422ded = \_0x4c771b(\_0x4e0309 + \_0x11dbad())\_0x4e0309是个获取时间戳，\_0x11dbad()产生了一个UUID，两个进行了字符串拼接后，传入\_0x4c771b函数进行运算。

![](https://attach.52pojie.cn/forum/202509/04/201436dq07o1gmfkmr0ygf.png)

'token': \_0x4e0309;\_0x4e0309 = \_0x4c771b(\_0x4e0309 + \_0x3fedba + \_0x589b78 + \_0x422ded) + ':' + (parseInt(\_0x4e0309) + 0x493e0) || ''token也是先用\_0x4e0309获取时间戳，\_0x3fedba是固定的captchaId这个参数，\_0x589b78是固定的slide字符串，\_0x422ded就是上面计算的captchaKey值。
这些值拼接后继续传入\_0x4c771b函数进行运算。
最后在进行一次拼接。
'iv': \_0x4015b8[\_0x5876dc(0x33f)];\_0x4015b8['IMAGE\_VERIFY\_TAG'] = \_0x4c771b(\_0x3fedba + \_0x589b78 + Date[\_0x5876dc(0x3d5)]() + \_0x11dbad())iv值跟token算法大同小异，看起来复杂，其实就是不同字符串拼接。
也是传入\_0x4c771b函数进行运算。因此顺着\_0x4c771b函数往下扣就行。
扣完就一百来行代码。结果如下
![](https://attach.52pojie.cn/forum/202509/04/201456pdd4nzj1zunnldtr.png)
有了参数及验证码地址。
接下来就可以识别了。直接用ddddocr就行。
识别率基本百分百。

[Python] *纯文本查看*

```
det = ddddocr.DdddOcr(det=False, ocr=False)
```

接下来。我们再看验证码的发包。

![](https://attach.52pojie.cn/forum/202509/04/201514kkvvb5slpofvyosv.png)

可以看到只有两个参数，一个是IV，我们上面已经解决了。
还有个textClickArr参数，按参数字面意思，只传入了一个X的坐标值。
为了保险。我们看一下调用。
照常点进调用栈。直接就出来了。

![](https://attach.52pojie.cn/forum/202509/04/201529f92vgvbppzg9qq9g.png)

我们都打上断点。
跟下去可以看到这么一个代码i ? e : l ? t.call(e) : u ? t(e[0], n) : o核心是t(e[0], n)这个函数，获取了滑块的最左边的坐标

![](https://attach.52pojie.cn/forum/202509/04/201547hwiddwmwwaei9dat.png)

然后进行了运算
parseInt(\_0x12404f) - \_0x4015b8[\_0x58cb01(0x25c)][\_0x58cb01(0x30c)]\_0x12404f
就是x的值,
减去\_0x4015b8[\_0x58cb01(0x25c)][\_0x58cb01(0x30c)]
生成的8,就是发送的参数因此我们在ddddocr中识别的x坐标减去2。

![](https://attach.52pojie.cn/forum/202509/04/201649evppxglty94w4qxx.png)

接下来发送成功后获取到validata值，随着login登录添加到post参数中data就行了。
因为登录没有加密。我们就不看了。
直接看验证码，可以看到10次发送，成功率百分之百。
