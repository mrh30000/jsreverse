# 签名型网盘与助手类脚本：判型 → 还原 → 边界

**唯一权威源。** 本文回答两件事：① **什么时候真的需要还原算法**；② **助手类脚本（油猴 / 解析站）的"验证"到底是真校验还是表演**。

## §1 先判型：协议型 vs 算法型

网盘请求上的"签名类"字段分两种，处置方式完全不同：

| 型 | 特征 | 判据（30 秒可做） | 处置 |
| --- | --- | --- | --- |
| **协议型** | 字段是**服务端下发的一次性 token**（`sign` / `skdklds` / `websign` / `st`） | **原样重放**同一个字段 → 通过 | 不需要算法；把"取值 → 带上"做对即可 |
| **算法型** | 字段由客户端**本地算出**（`x-signature` / `auth` / `encryptHex`） | 原样重放 → 失败；同一输入两次结果不同或必须与会话一致 | 需要还原：先找 writer，再定算法族 |

**判型只需一次实验**：把抓到的那条请求**逐字重放**（同 UA / 同 Cookie / 同 body）。
通过 ⇒ 协议型（99% 的 `sign` 属于这一型，别浪费时间读 JS）；
不通过 ⇒ 再看"是不是每次不一样"，是则算法型。

> 这一条与 `web-reverse-algorithm` 的"先判题型再判阻塞点"是同一原则；
> 本技能只保留**网盘场景下怎么判**。

## §2 阿里云盘：`x-device-id` + `x-signature`（算法型）

### §2.1 现象与入口

- 报错字面量：**`invalid X-Device-Id`**；
- 只有**取下载链接**这类接口需要校验（列目录不需要）；
- 抓包看"发起的程序" ⇒ 直指 `bundle.js`；搜 `createSession` 直达。

### §2.2 结构（三条可复核结论）

1. **`x-device-id` = 一个 UUID 字符串**，随机生成但**以 `userId` 为种子** ⇒ 同一账号稳定、不同账号不同（避免风控）。
2. **私钥由 `userId` 派生**（原文口径：对 `userId` 做 SHA-256），登录时重新生成；
   **只需要私钥就能推出公钥** ⇒ 说明不是 RSA（RSA 不可能从私钥单独反推公钥）。
3. **公钥算法是 `secp256k1`（ECC）**，不是 RSA。
   判据：断在 `getPublicKey` 里，看到的是**乘法运算**而不是模幂；
   且 `e` 从来不是 `65537`。
   `04` 前缀是**未压缩 ECC 公钥**标记，是"后续转 HEX 时手工加上的"，不是算法的一部分：

   ```js
   t ? `${this.y & o ? "03" : "02"}${e}` : `04${e}${A(this.y)}`
   ```

### §2.3 签名体（可复算的公式）

```
明文  = appId + ":" + deviceId + ":" + userId + ":" + nonce
摘要  = SHA-256(明文)
签名  = ECDSA_secp256k1_sign(摘要, privateKey)
x-signature = hex(签名) + "01"
```

- `nonce`：**初始 0**，超时后更新（**每次 +1**，更新时间随机）⇒ 它只起"限位"作用；
- 末尾那个 `"01"` 来自 `concat(u)`，`u` 来自 `recovered` 的下一段流水线（原文未给出更细语义）；
- 公钥要**上报**：先请求 `get_public_key`，把 `"04" + pubkey` 发给服务端，后续用这个密钥对签名。

### §2.4 三个实测坑

| 坑 | 说明 | 处置 |
| --- | --- | --- |
| **签名不可复用** | 非对称签名同一内容每次结果不同，但服务端**不做重放校验** | 每次现签 |
| **必须原样透传** | `createSession` 用过的 `x-signature` 必须**原封不动**带给其他 API；密钥对一致、内容一致也不接受新签名 | 把 `createSession` 的返回值当会话凭证持有 |
| **旁路诱惑** | "列目录接口会携带下载链接" —— 于是有些脚本至今能用 | ⚠️ 这是**站点的实现漏洞**，不是可依赖的接口；写进结论时要标注"旁路、随时可能关闭" |

### §2.5 复算

`scripts/aliyun_ecc_sign.py` 用**纯标准库**实现 secp256k1 公钥推导（无 `ecdsa` / `coincurve` 依赖），
并用源文给出的真实私钥做 oracle：

```
私钥(32 字节) = 175,87,171,214,222,196,127,36,25,50,237,179,71,81,49,196,
                250,103,115,203,138,179,192,182,43,175,233,72,200,14,64,254
公钥(未压缩, 去 04 前缀) = 3e2a3bbd2dfe8675bc40b0b0af6a558421b827b5ad022c8d305eb861b9bfdcc4
                            8aea1243df77a6298dfd5cf692a407852b3fd996ea5a13ae213c4380bb7b8d0d
```

`--selftest` 会逐字符比对这两串（源文原样给出，因此是**外部可复核常量**）。

## §3 助手类脚本（油猴 / 篡改猴）：先看有没有网络请求

**判据只有一条，而且极其机械**：点下去之后 **有没有产生网络请求**。

| 现象 | 结论 | 处置 |
| --- | --- | --- |
| 点击后**没有任何请求** | **本地校验**（前端表演） | 找到那个判断条件，把它改成恒真 |
| 点击后请求了第三方接口 | **服务端校验** | 走协议还原；同时审计脚本的外联面 |

**本地校验的典型形态**（原文实测）：

```js
async initDialog() {
  let result = await Swal.fire({ … 输入框 … });
  if (pan.num === $('#init').val()) {          // ← 就是这一行
    base.setValue('setting_init_code', pan.num);
    …history.go(0)…
  } else { …重新输入… }
}
```

⇒ 把 `if (pan.num === $('#init').val())` 改成 `if (true)`，校验即消失。
`pan.num` / `pan.img` / `pan.init[]` 全部来自脚本内的配置对象，**服务端从未参与**。

### §3.1 审计清单（用助手脚本前必做）

| 项 | 看什么 |
| --- | --- |
| `@match` / `@include` | 它会作用在哪些站点上 |
| `@grant` | 有没有 `GM_xmlhttpRequest` / `GM_setValue` 这类越权面 |
| `@connect` | 允许它连哪些域 |
| 远程配置 | 是否有"启动时拉配置"（**静态审计必然漏**：选择器、轮询间隔、跳转前缀都可能由服务端下发） |
| 本地存储 | 它往 `localStorage` / `GM_setValue` 写了什么 |

> ⚠️ **"网络面板看不到 ≠ 没有外联"**：`GM_xmlhttpRequest` 不总是出现在页面网络面板里。
> 要同时 hook `GM_xmlhttpRequest` / `fetch` / `XHR`，必要时做系统级抓包。
> 这一条与 `web-malware-forensics` 的扩展 / 油猴审计是同一口径。

## §4 解析站 vs 本地解析：边界与红线

| 形态 | 谁在解析 | 代价 | 风险 |
| --- | --- | --- | --- |
| **本地解析**（本技能） | 你的代码 | 要跟代际变化 | 无第三方依赖，最可控 |
| **解析站**（服务端代取） | 对方服务器 | 免维护 | **对方拿到你的分享链接与提取码**；可用性、稳定性、合规性都不可控 |
| **客户端助手**（油猴 / 装机版） | 浏览器内脚本 | 免维护 | 脚本可读写你的登录态；可能夹带外联与返利 |

**红线**：

- 只解析**分享者公开分享**的链接；提取码由分享者提供；
- **不**做口令爆破、**不**做目录越权遍历、**不**绕过账号权限；
- 用第三方解析站/助手前，先按 §3.1 审计；
- 把"旁路接口"（如 §2.4 的列目录顺带返回下载链接）写进结论时，必须同时写"这是实现漏洞、非契约"。
