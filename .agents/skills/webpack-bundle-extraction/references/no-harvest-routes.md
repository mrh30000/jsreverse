# 免抠路线与「该不该抠」决策

> 本文件是「**不抠代码**」这条路的唯一权威源，也是三条路线的**选择总闸**。
> 抠取流程见 `harvest-routes.md`；环境交接见 `node-reuse-and-env-handoff.md`。

## 一、决策：先问三个问题

1. **调用频次**：一次调用（研究/复现）还是长期批量（爬虫/自动化）？
   - 一次 → 免抠（RPC / 无头浏览器）性价比高一个数量级。
   - 长期批量 → 抠代码；RPC 会随页面关闭而失效。
2. **目标函数的位置**：纯算法模块，还是**运行在风控 SDK 内部**（依赖大量浏览器状态）？
   - 后者抠出来也跑不起来（缺环境），扣的收益低于补环境。
3. **闭包规模**：`closure` 报出来的可达模块数占整包多大比例？
   - >70% ⇒ 抠取收益很低（体积没降多少），但仍可能值得做（因为**确定性**比体积重要）；
   - 闭包里有大量 `null`（异步 chunk）⇒ 先走免抠。

## 二、免抠三条路

### 2.1 无头浏览器（Playwright / Puppeteer）

在页面上下文里直接调用真实函数。最省事，代价是每台机器要装浏览器。

```js
const v = await page.evaluate((arg) => window.__realSign(arg), payload);
```

适用：调用量中等、能接受浏览器常驻；或**只是想拿一批 oracle 值来对拍自己的纯算实现**。

### 2.2 RPC / WebSocket 桥

在页面里注册一个函数，把结果通过 WebSocket 送回本地脚本。**页面不能关**是硬约束。

```js
// 页面 Console 注入（示意）
const ws = new WebSocket('ws://127.0.0.1:12080/ws?group=test&name=test');
const demo = new Hlclient('ws://127.0.0.1:12080/ws?group=test&name=test');
demo.regAction('hello', function (resolve, param) {
  resolve(realSign(param));            // resolve 的值就是要回传的结果
});
```

```python
# 本地调用（示意）
requests.get('http://127.0.0.1:12080/go', params={'group': 'test', 'name': 'test', 'action': 'hello', 'param': 'x'})
```

三个必须知道的点：

1. **`group` 与 `name` 只是分组标识**，随便填，但两边必须一致；返回 JSON 里会带上 `action` 名。
2. **HTTPS 页面连普通 `ws://` 可能被安全策略拦**：本机 `127.0.0.1` 通常放行；否则要起 `wss://` 并配证书。
3. **`resolve` 才是回传点**，返回值不会自动回传——注册的函数必须显式调用 `resolve(...)`。

**替代形态**：不引入框架，自己写一个极简桥也够用（页面里 `window.__sign = (p) => realSign(p)`，
本地用 CDP `Runtime.evaluate` 调用）。判据是**调用方能不能稳定复现一次调用**，而不是用了哪个框架。

### 2.3 WASM 模块复用

加密实现在 wasm 里时，截获导出函数比读 wasm 算法快得多。
`wsam-reverse` 有专门的路线选择表与 `importObject` 代理技巧；
媒体流场景另见 `../../stream-drm-reverse/SKILL.md` 的 F 层。

## 三、三条路的对照表

| | 抠代码 | 无头浏览器 | RPC 桥 |
| --- | --- | --- | --- |
| 一次性成本 | 高（找加载器 + 补闭包 + 对拍） | 低 | 低 |
| 单次调用成本 | **极低**（纯本地计算） | 高（启动/渲染） | 中（跨进程 IPC） |
| 稳定性 | 站点改版即失效（模块 id 漂移） | 高 | 低（页面一关就断） |
| 可离线复跑 | **是** | 否 | 否 |
| 适合 | 长期批量、要沉淀成纯算实现 | 快速取 oracle、验证假设 | 短期、混淆极强、抠不动 |

**推荐的组合打法**：**用免抠路线取 oracle，用抠代码路线做最终实现**。
先无头/RPC 拿到 20 组「输入 → 输出」，再抠代码，抠出来的产物与这 20 组逐字节对拍——
这就是 `harvest-routes.md` §4 那条「端到端数值对拍」的最省力实现方式。

## 四、反例黑名单

- **不要为了「优雅」去抠一个只调用一次的站点。** 抠取代价的量级是小时级，RPC 是分钟级。
- **不要用 RPC 跑生产批量的主链路。** 页面关闭、进程重启、证书过期都会让它断；
  RPC 的定位是**调试期与取 oracle**。
- **不要在没确认闭包完整性之前就宣称抠取成功。** 「跑起来没报错」不是验收，
  见 `harvest-routes.md` §4 的三个断言。
- **不要把「抠出来能跑」当成「算法已还原」。** 抠取给的是**可复用的黑盒**，
  纯算实现是另一件事（`../../web-reverse-algorithm/SKILL.md`）。
- **不要在抠取过程中顺手反混淆。** 两个目标混做会让失败原因不可判，见 `harvest-routes.md` §6 的边界声明。
