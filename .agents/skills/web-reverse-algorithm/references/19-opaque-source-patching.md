# 19 · 不透明源码的定向补丁（PHP 混淆器 / 服务端授权 / 自毁拦截）

> **定位**：本文件处理一类**「源码在手、但方法体不可读」**的题 —— 站点/主题/插件用商业混淆器
> （本批样本是 **Z5Encrypt**）把 PHP 方法体整体加密成
> `签名 { $随机变量='密文'; return eval(解密器($随机变量));$_SERVER; }`。
> **目标不是解密**，而是**只替换那几个决定「放行/拦截」的方法体**，把判断改写成常量。
>
> **它不替代谁**：
> - `02-algorithm-families.md` **§七「客户端授权 / 许可证校验题」** 是**同一族的姊妹篇**（那边是**前端 JS** 的
>   33 进制许可证算法，目标是「让一个布尔判断变成 `true`」）。**先读 §七 的判据表**，再回到本文。
> - `07-antidebug-and-live-patching.md` **§5.8** 已立了同一范式的**浏览器侧**版本
>   （「把检测的返回值改写成常量，最小干预」）。本文是它的**服务端 PHP 版本**，并把「改写」升级成
>   「**整段方法体替换**」——因为这里的原文根本读不懂，没有「改一行」的余地。
> - `../../miniprogram-reverse/references/request-crypto-and-sign.md` §3.1 的「拿 oracle：把方法体直接替换掉」
>   是同一动作在**小程序**载体上的用法（那边是为了**当加解密 oracle 用**，这边是为了**改授权结果**）。
>
> **⚠️ 合规边界（先读这句）**：本文所有内容用于**理解混淆结构与做技术验证**。
> 本库**不收录**任何成品注册机 / 破解包；§7 明确写清「哪些方法**绝不能动**」正是为了让读者明白
> **「能改」不等于「该改」**——删掉业务依赖链会让整个站点崩掉。

## §0 三十秒判据：这题是不是「不透明源码定向补丁」

| 现象 | 判断 | 去哪一节 |
| --- | --- | --- |
| PHP 文件里能看到**函数签名**，但花括号内是一串**二进制密文 + `return eval(...)`** | **本文**：混淆器产物 | §1 |
| 每个加密方法都以 **`);$_SERVER;}`** 结尾 | Z5Encrypt 族（**这是定位方法边界的唯一锚点**） | §1.2 |
| 整个文件开头是一大块 `gzinflate` / `base64_decode` 的全局混淆代码 | 解密器定义在**文件头**，不在方法内 | §1.2 |
| 方法内的变量名是**每次都不一样的 latin1 乱码**（`$é&#229;&#229;` 一类） | **不要试图按变量名匹配** | §1.2 |
| 想把 `if (false)` 直接塞进去，但**根本找不到可读的判断点** | 判断点在**别的方法**里，且是不可读的 | §2 |
| 目标不是「拿数据」而是「**让功能开关变 true**」 | 同族（`02-algorithm-families.md` §七） | 先读 §七判据表 |
| 改完**没有任何变化**（不报错、行为照旧） | 真正生效的是**另一处**，或方法被**重复定义** | §3.5 / §8 |
| 站点/主题**突然自己删文件**、后台报错但日志为空 | 存在**自毁 / 反篡改**方法，必须与授权方法**一起拦** | §6 |

## §1 结构判据：Z5Encrypt 族的解剖

### §1.1 一个加密方法的完整形态（源文逐字）

```php
public static
function is_aut(){$é&#229;&#229;='uVMO\x14A\x10}&#179;\x88°ì\x08\x0a...数百字节二进制密文...'."\0".'...';return eval(解密函数调用(加密变量));$_SERVER;}
```

拆成五段（**这五段就是判据**）：

| 段 | 内容 | 作用 |
| --- | --- | --- |
| ① | 修饰符（可能**单独占一行**：`public static` 换行后才 `function`） | 见 §3.4：**漏补会静态调用失败** |
| ② | `function 方法名(参数) {` | **必须保留**：调用方按名字与签名调 |
| ③ | `$随机变量 = '二进制密文'."\0".'…';` | 变量名每次都变 ⇒ **别按名字匹配** |
| ④ | `return eval(解密器($随机变量));` | 真正的逻辑在 eval 里 ⇒ **读不到** |
| ⑤ | `;$_SERVER;` + `}` | ★ **方法边界锚点** |

### §1.2 三条结构判据（源文原话 + 本库复核）

1. **`);$_SERVER;}` 是定位方法边界的唯一锚点。** 源文明确写了「唯一」。
   `$_SERVER;` 在 PHP 里是一条**无害的表达式语句**，且写在 `return` **之后**（不可达）
   —— 它存在的唯一目的就是**当锚点**。
   ⚠️ **`$_SERVER;` 必须在代码层匹配**：密文字符串里**完全可能**出现同形片段（源文自己就警告
   密文含 `}` / `;`）⇒ **朴素的 `indexOf` 会切错，而且不报错**。见 §3.3 与工具自检第 2 组。
2. **解密函数定义在文件开头的全局混淆块里**，整个文件是一个巨大的 `gzinflate` 压缩块。
   ⇒ **不要试图「先解出解密器再解密」**：那是另一条（更贵的）路线，且本文的前提就是**不解密也能干活**。
3. **方法内的加密变量名每次不同**（随机 latin1 字符串）。
   ⇒ **判据**：任何「按变量名定位」的脚本都会**跨文件/跨版本失效**；定位只能靠**锚点 + 函数名**。

### §1.3 规模感（用于估工期）

源文样本：**15 个文件、约 149 个加密方法**，其中核心授权文件 `inc/code/code.php` 有 **33 个**。
⇒ **判据**：**不要逐个方法读**。先跑 `--list` 把「混淆 / 明文」分类打出来，再只对**授权链上的方法**动手。

## §2 判断点在哪：先读调用方，再决定改谁

**这是本范式最容易做错的一步**。源文的做法值得照抄：

1. 从**业务入口**往下读（源文从 `options-module.php` 的授权面板开始）：
   ```php
   if (!ZibAut::is_local()) { /* 非本地 → 显示授权状态面板 */ }
   else { /* 本地 → “暂时无需授权” */ }
   ```
2. 由此**推导出方法语义**（源文列的四条，逐字）：
   - `is_local()`：`true` = 本地环境无需授权；`false` = 走正式授权路径
   - `is_aut()`：**「是否已授权」的核心方法**（返回 `true` 后，前台付费内容、后台功能开关、商城/BBS 状态**全部认为已授权**）
   - `is_ok($data)` / `is_singok($data)`：远程授权码验证 / 数字签名校验
   - `curl_aut()` / `http_request()` / `timing_aut()`：**远程通信**（要拦）
   - `delete()`：**检测到篡改时删除主题文件**（自毁，要拦）
3. **只在读完调用方之后才动手**。

> ★ **可迁移判据**：**「改哪个方法」由调用方决定，不由方法名决定。**
> 源文的 `is_aut()` 名字看不出是「总开关」，是从 `options-module.php` 的用法反推出来的。
> 反过来，`zib_is_local()`（在 `tool.php` 里）名字很像，但**实际由 `code.php` 的 `is_local()` 兜底**
> ⇒ 源文对它的处置就是「`return "";`，已由 code.php 处理」。

## §3 作业流程（五步，缺一步就会「改了没变化」）

### §3.1 第 1 步：枚举与分类

```bash
node .agents/skills/web-reverse-algorithm/scripts/php_opaque_patch.js --list inc/code/code.php
```

输出形如：

```text
函数/方法共 6 个：
  [混淆] public static is_local  体长=77
  [混淆] public static is_aut  体长=54
  [混淆] (无修饰符) delete  体长=38
  [明文] (无修饰符) zib_init_add_action  体长=34
```

**分类判据**（两条**都要**成立才算混淆产物，且都必须在**代码层**成立）：
① 方法体内（含结尾那个 `}`）出现锚点 `);$_SERVER;}`；② 方法体内有 `return eval(`。
⇒ 只有 ① 没有 ② 的（例如某个明文函数只是**在字符串里提到**这个锚点）**不能动**。

### §3.2 第 2 步：写「替换计划」（一个 JSON）

```json
[
  {"name": "is_local",  "body": "return false;"},
  {"name": "is_aut",    "body": "return true;"},
  {"name": "curl_aut",  "body": "return \"\";"},
  {"name": "delete",    "body": "return \"\";"}
]
```

★ **计划必须显式写全**。源文的价值就在这份清单：`code.php` / `aut.php` / `tool.php` /
`new_aut.php` / `options-module.php` 五个文件里**分别该动哪些**，以及**哪些绝不能动**（§5）。

### §3.3 第 3 步：整段替换方法体（不是「改一行」）

```bash
node .agents/skills/web-reverse-algorithm/scripts/php_opaque_patch.js \
  --patch inc/code/code.php --out out/code.php --plan plan.json
```

**算法**（保留签名，切掉整个方法体）：

```text
before = 源码[0 : '{' 之后]
after  = 源码['}' 之后 : ]
out    = before + ' return <值>; }' + after
```

★★ **两个必须自己实现的点**（源文那版 `nuke()` 有，但**照抄会踩**）：

| 点 | 源文写法 | 问题 | 本文做法 |
| --- | --- | --- | --- |
| 锚点匹配 | `code.indexOf(SERVER_END, openBrace)` | **朴素匹配**：密文字符串里出现同形片段就切错，且**不报错**（表现为括号不配平 / 留下 `';return eval(...)` 的尾巴） | **字符串感知扫描**（跳过 `'…'` / `"…"` / `//` / `#` / `/*…*/`）后再匹配 |
| 切点 | `termIdx + SERVER_END.length` | 依赖「锚点的最后一个字符恰好是方法体的 `}`」；锚点位置一变就错位 | **用配平得到的 `endBrace` 切**，不依赖锚点长度 |

> **工具自检第 2 组就是拿这两条做的反面夹具**：夹具里第一个方法的**密文串内**故意塞了一个
> `});$_SERVER;}`。朴素切法**照样返回成功**，但产物**括号不配平**、目标方法里还挂着
> `return eval($DEC($v));$_SERVER;}` 的尾巴；字符串感知切法干净闭合。
> ⇒ **判据：这类工具的「成功」返回没有任何意义，必须自己过一遍配平。**

### §3.4 第 4 步：补修饰符（★ 顺序敏感，反着做会「两头都没了」）

源文的两个动作：

```js
// ① 为所有修补方法添加 static
code = code.replace(new RegExp('function\\s+' + m + '\\s*\\(', 'g'), 'public static function ' + m + ' (');
// ② 删除残留的单独 public static 行（否则产生重复修饰符）
code = code.replace(/^(\s*)public\s+static\s*[\r\n]+(?=\s*(?:public\s+static\s+)?function)/gm, '');
```

**为什么要补**：BBS 论坛与商城模块通过 `ZibAut::is_aut()` 这类方式**静态调用**授权方法；
修补后的方法**缺少 `static` 关键字，静态调用会失败**。

**为什么要清残留**：原文的修饰符常常**单独占一行**（`public static\nfunction is_aut(`），
替换后变成 `public static\npublic static function is_aut(` ⇒ **重复修饰符 = PHP 致命错误**。

★★ **顺序坑（本批实测）**：如果**先补后清**，而「补」的判据是「前面已经有 `public static` 就不补」，
那么**残留行会被当成「已有」⇒ 不补**；紧接着「清」把残留行删掉 ⇒ **`public static` 彻底消失**。
⇒ **正确顺序：先清残留，再按「缺才补」补。** 工具把两步合成一次幂等调用，自检第 4 组断言「跑两次结果不变」。

### §3.5 第 5 步：机械校验（不做这步就等于没做完）

| 检查 | 判据 | 为什么 |
| --- | --- | --- |
| **括号配平** | `( )` 与 `{ }` 都余 0（**字符串感知**统计） | PHP 只在**运行期**才报语法错，页面上表现为「白屏/500 但日志为空」 |
| **无重复修饰符** | `public static public static` 出现 **0** 次 | 见 §3.4 |
| **目标方法内无 `eval(`** | 出现 0 次 | 出现 ⇒ 替换没覆盖干净 |
| **非目标方法逐字节不变** | diff 只应出现在计划内的方法上 | 见 §5：动了依赖链就崩 |

## §4 返回值类型怎么选（源文给了三条理由，**照抄即可**）

**这是本范式里最容易被忽略、却最容易出问题的一环。** 返回值不是「随便给个真值」：

| 方法 | 返回值 | 源文的理由（逐字要点） |
| --- | --- | --- |
| `curl_aut()` / `http_request()` / `timing_aut()`（远程通信） | **`return "";`** | ★ **不要用 `false`**：「调用方可能对返回值做字符串操作或数组访问。返回空字符串比 `false` 更安全——不会触发 `if ($result === false)` 这类严格比较」 |
| `isok($code)` | `return md5("bypass");` | 「调用方可能对返回值做 **hash 比较**。返回合法 md5 值比返回 `true` 更不容易触发异常路径」 |
| `aut()` | `return array("result"=>true,"msg"=>"ok");` | 「返回值会经过 `json_encode()` 发送给前端。返回正确的**数组结构**确保 JavaScript 端不报错」 |
| `is_local()` | `return false;` | 语义：`false` = 走正式授权路径（**故意的**，为了进授权面板分支） |
| `is_aut()` / `is_ok()` / `is_singok()` / `aut_required()` / `update_ok()` | `return true;` | 布尔语义明确 |
| `delete()` / `save_aut_code()` / `get_aut_code()` / `get_url()` 一类 | `return "";` | 空串对调用方最中性 |

> ★★ **可迁移判据（本范式最值钱的一条）**：**「返回值类型」由「调用方怎么用这个值」决定**，
> 不是由「你想让它表示什么」决定。**动手前先把调用方那一行读出来**：
> 它做字符串拼接就给 `""`，做 `json_encode` 就给数组，做 hash 比较就给一个合法 hash，
> 只有明确做布尔判断时才给 `true` / `false`。

## §5 依赖链：★ 哪些方法**绝不能动**

源文的自陈（**这是本文最重要的一条经验**）：

> 「我开始**全把加密都干掉，结果全局崩了**，后面仔细发现，接下来**只修改授权/自毁相关方法**，
> 保留所有业务逻辑加密代码。」

崩溃的原因是**隐式运行时依赖链**（源文给的结构图，逐字）：

```text
functions.php
└─ inc.php
   ├─ require.php
   │   ├─ zib_init_add_action()   [eval] → 动态定义 OB() V() Va() S() U() v() Z() Q()
   │   └─ zib_admin_tool_action() [eval] → 注册 WordPress 管理后台钩子
   ├─ file.php
   │   └─ ZibDB::query() [eval] → 内部调用 OB() V() Va() 等 VM 函数完成查询构建
   ├─ shop/class.setup.php  [eval] → 商城初始化
   └─ zibpay/ajax-class.php [eval] → 支付处理
```

**判据**：`require.php` 的 `zib_init_add_action()` 的 eval 代码**动态定义了 8 个短名全局函数**
（`OB` / `V` / `Va` / `S` / `U` / `v` / `Z` / `Q`）——**这些是 `ZibDB` 与其他业务代码的运行时依赖**
⇒ **`require.php` 不能修改**。

> ★★ **可迁移判据**：**混淆代码里的 `eval` 不一定是「判断逻辑」，也可能是「定义业务函数」。**
> 判断方法：**看它的返回值有没有被别处用到**。
> - 返回布尔 / 被 `if` 吃掉的 ⇒ **可改写**（授权类）
> - 返回 void / 定义函数 / 注册钩子的 ⇒ **绝不能动**（`zib_init_add_action` / `zib_admin_tool_action`）
>
> ⚠️ **源文自陈「做事要做完美」之后仍然把 `new_aut.php` 的这两个方法替换掉了**
> （§`10.inc/code/new_aut.php` 表里 `zib_init_add_action()` → `return "";`）——
> 这与它自己在 §3.1 写的「`require.php` 不能修改」**存在口径张力**（两个文件里的同名方法？还是同族不同文件？）。
> **本文如实登记该矛盾，不替源文裁决**；实操建议：**先只动授权判断，跑通之后再考虑要不要碰初始化钩子**。

## §6 自毁 / 反篡改：必须与授权方法**一起**拦

源文原话：「这里**特别恶心**，检测到篡改时调用此方法**删除主题文件**，
我开始以为是我本地的环境问题，一直修补了半天」。

| 方法 | 处置 | 说明 |
| --- | --- | --- |
| `delete()` | `return "";` | **自毁入口**（删主题文件） |
| `zib_admin_delete_aut()` | `return "";` | 自毁入口（另一处） |
| `zib_admin_aut_add_action()` / `zib_admin_curl_aut()` | `return "";` | 注册授权相关 Hook / 发授权请求 |
| `timing_aut()` | `return "";` | **定时**自动授权检查（不拦会周期性触发） |

★★ **可迁移判据**：**「文件被删 / 站点自己崩」不是环境问题，是反篡改在生效。**
排查顺序：① 先看有没有 `delete` / `unlink` / `rmdir` 一类的短方法名；
② **拦自毁要先于拦授权**（否则你每改一次就少一个文件）；
③ 源文结尾自己留了一句「**不排除是否还有自毁机制没改到**」⇒ **在非正式环境里测**。

## §8 排错表

| 现象 | 首查 | 次查 |
| --- | --- | --- |
| 改完**毫无变化**（不报错、行为照旧） | 真正生效的是**另一处**（同名方法在别的文件 / 别的类） | 源文自己的教训：`if (false)` 只在「校验全在自己机器上」时有效（见 `02-algorithm-families.md` §七「边界」） |
| 站点**白屏 / 500**，日志为空 | 括号配平（§3.5） | 重复修饰符 `public static public static` |
| 页面**报重复定义 / 致命错误** | 修饰符残留没清（§3.4） | 同名方法在多个文件里都改了 |
| 静态调用报错（BBS / 商城模块） | 漏补 `public static`（§3.4） | 补了但被残留清理连带删掉（**先补后清的顺序坑**） |
| 前台 JS 报 JSON 解析失败 | 某个方法该返回**数组**却返回了 `true` / `""`（§4） | 该返回合法 hash 的返回了布尔 |
| **文件在减少 / 站点自己崩** | 自毁方法没拦（§6） | `timing_aut` 定时触发 |
| 替换「成功」但方法体没变 | 锚点匹配落进了**密文字符串**里（§3.3） | 方法体里**有多个**同形锚点 |
| 换一个版本/文件后脚本全失效 | 按**变量名**匹配了（§1.2） | 按**行号**匹配了 |
| 改完能进后台，但**保存内容失败** | 授权面板分支进了，但**另一个保存链路的判断**没处理 | 源文提到「如果没授权是无法保存内容」⇒ 保存链路也读授权状态 |

## §9 源文缺陷与登记纪律（本批新收，**照抄会踩**）

1. **★ 源文的代码块被论坛做了 HTML 实体转义**：`$é&#229;&#229;`、`$&#190;&#169;&#1033;`、
   `$ò&#338;&#217;` 里的 `&#NNN;` **不是 PHP 语法**，是**二进制密文被转义后的残留**。
   ⇒ **不要把这些实体抄进代码**；它们只是「随机 latin1 变量名」的**显示形态**。
   **通用判据**：**源码里凡是 `&` 开头的实体残留，一律是「搬运产物」而不是源码**
   （与 `docs/references/verified.md` 批次 B38 登记的「HTML 命名实体残留族」同源）。
   ⚠️ 顺带一个**工具实现坑**：若你的扫描器把 `#` 当 PHP 行注释，`&#229;` 会让它**从 `#` 起整行失配**
   ⇒ 本批的工具自检第一版就踩了这个（夹具里留了实体，结果 `is_local` 被整行判成字符串）。
1b. **★★ 源文把 `_` 转义成了 `\_`（Markdown 转义泄漏进了代码块）**：
   帖子里的方法名逐字是 **`is\_local`**、**`is\_aut`**、**`curl\_aut`**、**`is\_singok`**、
   **`zib\_init\_add\_action`**、**`json\_encode`**，连**代码块里的 `function is\_local(){`** 也是转义的。
   ⇒ **判据：从论坛复制的 PHP 里出现 `\_`，一律先还原成 `_`，否则 PHP 直接语法错**
   （本批回源门禁用**两条负面针**钉死了这条：源文里**不存在**未转义的 `function is_local(`）。
   ⚠️ **这条对「按名字做替换」的工具是致命的**：若你的 `plan.json` 里写 `is_local`，
   而源文实际是 `is\_local`，**方法名匹配会全部落空**（`nop` 且不报错）。
   ⇒ 工具侧建议：匹配前先把 `\_` 归一化为 `_`，**并把归一化次数打进日志**。
2. **★ 源文的正则被 Markdown 吃掉了转义**：正文里出现
   `new RegExp('function\s+' + funcName + '\s*\([^)]*\)\s*\{')` —— 在 Markdown 里
   `\s` / `\(` 的**反斜杠会丢**，直接抄进 JS 会变成**非法转义**。
   ⇒ **判据：凡是「文档里给的正则」，落进代码前先 `JSON.stringify` 打出来看一遍**。
3. **源文那段 `public static` 残留清理的正则本身是坏的**：
   `(?=\s\*(?:public\s+static\s+)?function)` 里多了个 `*`、少了个 `(`（应为 `\s*(?:…)?function`）。
   ⇒ **别抄，自己写并跑夹具**。
4. **`nuke()` 的切点依赖锚点长度**（§3.3）：能跑通是因为样本恰好规范，不是因为它健壮。
5. **§5 登记的口径张力**：源文一边说「`require.php` 不能修改」，一边把 `new_aut.php` 里的
   `zib_init_add_action()` 替换掉。**本文如实登记，不裁决**。
6. **源文结尾自陈「不排除是否还有自毁机制没改到」** ⇒ 这是**单样本、未穷尽**的作业记录，
   **不是「照做就一定安全」的配方**。

## §10 工具

`scripts/php_opaque_patch.js`（零依赖，`--selftest` **40 项断言**）：

```bash
node .agents/skills/web-reverse-algorithm/scripts/php_opaque_patch.js --list  <file.php>
node .agents/skills/web-reverse-algorithm/scripts/php_opaque_patch.js --patch <file.php> --out <out.php> --plan plan.json
node .agents/skills/web-reverse-algorithm/scripts/php_opaque_patch.js --selftest
```

| 能力 | 说明 |
| --- | --- |
| `listFunctions` | 字符串感知地枚举函数/方法（修饰符、签名、体、`{}` 配平位置） |
| `looksOpaque` | 两条判据（代码层锚点 + 代码层 `return eval(`）**同时**成立才算混淆产物 |
| `patchBody` | 整段替换方法体；`{naive:true}` 可复现源文的朴素切法（**用于自检对照，不要用于生产**） |
| `ensureStatic` | 先清残留、再按「缺才补」补 `public static`，**幂等** |
| `balanceCheck` | 字符串感知的 `()` / `{}` 配平（替换后**必须**过） |
| `normalizeMdEscapes` | 把论坛帖泄漏进代码块的 `\_` 还原成 `_`，**并回报归一化处数**（见 §9.1b） |

**自检覆盖面**（7 组）：枚举与分类 · 字符串感知 vs 朴素切法（**反面夹具**）· 逐方法替换后的结构不变量 ·
`ensureStatic` 幂等 · 对未混淆方法替换必须失败 · 配平检查能抓出人为破坏 ·
**Markdown 转义泄漏归一化**（`is\_local` → `is_local`，见 §9.1b）。
