# 平台签名的跨平台共性规律（蒸馏自 24 个蓝图 / 36 篇来源文章）

> 本文件**只写跨平台共性**。单个平台的参数分解、取值来源、排查步骤一律看 `data/blueprints/<id>/`。
> 两者分工：蓝图 = 「这个平台的这个参数怎么生成」；本文件 = 「这一整类参数**反复踩的坑**」。
> 所有结论都可在某条蓝图的 `mutations[].symptom_if_wrong` 与 `metadata.sources` 里找到出处。

## 一、先量这四件事，再决定要不要读代码

| 观测量 | 能直接排除掉的可能 |
| :--- | :--- |
| **输出长度** | 32 = MD5 hex；40 = SHA1 hex；64 = SHA256 hex；44 = base64(32B)；固定 44/64 且带字母 = 大概率自定义表 base64 |
| **输出字符集** | 只含 `A-F0-9` → hex；含 `-_` 或大小写混排不规律 → **换表 base64**（见 §二） |
| **每次请求是否变化** | 不变 → 会话级 token（找 localStorage/cookie）；变 → 时间戳/随机数参与 |
| **响应里有没有 key/iv** | 有 → 直接写死或原样回环，**根本不用逆算法** |

**判据优先于算法**：上面四条能在 5 分钟内砍掉一半工作量，而读混淆代码要几小时。

## 二、第一坑：魔改 base64 / 魔改流密码（本簇出现频率最高）

已确证被换表或改算法的平台：抖音 `a_bogus`（自定义 64 字符表 + 非等长 RC4）、京东第 8 段（表内含 `-`/`_`，
输出**无 `=` 填充**）、知乎 `__zse_ck`（魔改 SM4 + 魔改 base64）、小红书 `x-s`（自定义 64 字符表）、
酷狗/QQ 音乐（换过的 hex 大小写与字母表）。

- **判据**：拿标准库解一遍 → 得到乱码 / 长度对不上 → 不要再怀疑自己的实现，**先去取表**。
- **取表的正确姿势是统计归纳，不是静态阅读**：小红书一文的作者用 **200 次调用**收集「密文字节 ↔ 输出字符」
  的映射统计出完整字母表；另一篇文章作者是用标准 base64 校验不通过才反推表的。
  **静态分析给出的表在混淆代码里几乎必错**（同一篇还把一个相邻的无关 ASCII 串 `exnsonixyangluo`
  误当成 XXTEA 密钥，真密钥是 `e6483ca2a1eed5e3`）。
- **流密码被改之后就不等长了**：抖音那篇原文的观察是「奇怪，长度并不相同，可能是哪里被魔改了」——
  **等长假设会把人带偏**。

## 三、第二坑：盐值的位置、形态与分隔符

四种都真实出现过，**没有任何一种可以"猜"**：

| 形态 | 实例 |
| :--- | :--- |
| 尾部定值拼在待签串末尾 | 抖音 `a_bogus`：URI 串尾拼 `dhzx` 再进 SM3 |
| 首尾各一次（双盐） | 酷狗：固定盐值在拼接串**开头和结尾各出现一次** |
| 无分隔符纯拼接（且按固定顺序） | 得物：参数名升序，`key` 与 `value` 直接相连；空数组只留下键名；酷狗同样无分隔符 |
| 换行分隔 + 空行有语义 | CSDN：`\n` 分隔，Method 与第一个签名头之间**恰好 3 个空行**（对应三个空值头） |

- **"参数顺序"本身就是签名的一部分**：B 站 `w_rid` 要求 `Object.keys().sort()` 后再拼；
  得物按升序；酷狗按写死的参数名序。
- **分隔符可能是"没有"**，也可能是 `&` / `|` / `\n` / 空串 —— 四种都要试，不要默认 `&`。

## 四、第三坑：时间戳

- **单位错一位就全错**：B 站 `wts` 是**秒**（`Math.round(Date.now()/1e3)`）；酷狗 `clienttime/mid/uuid` 是
  **13 位毫秒**且三者相同；拉勾 `time` 是 `int(time.time()*1000)`；京东 `t` 是毫秒。
- **服务端时间 ≠ 本地时间**：同花顺的 `TOKEN_SERVER_TIME` 会把时间编进 token，必须换成当前服务器时间。
- **hook 时不要把时间戳钉成定值**：抖音需要让每次 `Date.now()` 调用**递增**（作者用基准值递增），
  钉成定值反而与网站不一致。
- **随机数同理**：为了能对拍，需要显式固定（如把 `Math.random` 覆盖成固定值），
  但**交付产物里不能固定**。

## 五、第四坑：环境/指纹进了签名

- **UA 进签名是常态**：抖音（换 UA 即失效）、淘宝 `isg`（`a[8] = hash(navigator.userAgent)`）、
  同花顺（请求头 UA 必须与 `env.js` 内 `navigator.userAgent` **逐字符相同**，否则被判异常）。
- **字段白名单要照抄**：京东第 8 段**只有** `sua/pp/extend/random/v/fp` 参与；把 `wc/ua/av/pl/ml` 也塞进去
  会校验不过。**白名单比"多补几个更保险"重要**。
- **屏幕参数**：抖音 `arr_47` 来自 `innerWidth/innerHeight/outerWidth/outerHeight/availWidth/availHeight` 等，
  补环境缺字段 → 得到错误数组 → 最终串不匹配。
- **指纹检测点**：`navigator.webdriver`、`'$cdc_asdjflasutopfhvcZLmcfl_' in document`、
  `navigator.vendor/appVersion(/python/i)`、`'sgAppName' in navigator`、`navigator.getBattery`。

## 六、第五坑：补环境的四类共性事故

1. **宿主全局顶掉自补对象**：Node 内置 `navigator` 会覆盖自补的 `navigator`
   → 症状是**签名能生成、请求 403**。正确做法是把宿主全局先删掉再注入。
2. **Node 痕迹必须清**：加载 `env.js` 前 `delete global/process/require/module/exports/__dirname/__filename`；
   检测到 Node 环境时脚本会**直接返回空 token**（静默失败）。
3. **native 保护**：`toString` 要打 `[native code]` 标记，且原型链/描述符要成套（构造器 + prototype +
   实例 + 描述符 + native 标记）。
4. **必须真发请求 / 必须能退出**：有的环境壳里的 `XMLHttpRequest` 要基于 Node `https` 真发请求
   （否则 token 恒为本地兜底值）；有的脚本末尾有 `setInterval`，不 `unref` 会让 Node 进程**永不退出**。

## 七、第六坑：token 的来源与链式依赖

- **"远程下发"的 token 不能本地生成**：京东 `h5st` 的 token 必须走 `request_algo` 远程获取；
  本地兜底生成的是 `tk05`，抓包真值是 `tk03` → **请求 403**。
  **前缀就是来源标识，对比抓包即可一眼判断。**
- **链式依赖**：12306 的 `tk` 必须取上一步返回的 `newapptk`；拉勾的 `aesKey` 必须经 RSA 加密并通过
  `agreement` 接口验证后才有效；淘宝 `isg` 优先复用 `localStorage['isg__']` 旧值。
- **会话内可固定 ≠ 可硬编码**：B 站的 `imgKey/subKey` 实测固定、京东第 8 段被作者判断"几乎固定"，
  但两者实际都来自 localStorage / 含随机字段 —— **能取就不要写死**。

## 八、第七坑：编码层的三个反直觉处

- **大小写是签名的一部分**：QQ 音乐 `sha1` 要**大写 hex** 参与（字典键是大写 `A-F`，小写会查不到值）；
  酷狗 2020 版输出大写、2022 版输出小写；拉勾的 `code` 要 `.toUpperCase()`；QQ 音乐最终结果整体
  `toLowerCase()`。
- **base64 可能要裁字符**：QQ 音乐 `btoa` 后 `replace(/[\/+=]/g,'')`。
- **先过滤再编码，顺序不能反**：B 站 `w_rid` 是**先** `replace(/[!'()*]/g,'')` **再** `encodeURIComponent`。

## 九、第八坑：串的组成细节（差一个字符即全错）

- **query 可能被裁掉最后一个字符**：CSDN 的待签串是 `path + '?' + query[:-1]`。
- **空值不入串**：B 站只有 `null != h` 才 `push`。
- **同一逻辑量在两个地方叫不同名字**：京东 `signAppId`（第 3 段 `01a47`）≠ `appid`（`search-pc-java`）；
  同花顺 cookie 名是 `v`、localStorage 键是 `hexin-v` —— **读错一个就取不到值**。
- **body 参与签名时的序列化口径**：京东要求**无空格紧凑 JSON**（Python 端 `separators=(',', ':')`），
  否则与 JS 内部算出的 hash 不一致。
- **签名用的时间戳与请求里发的时间戳可能不是一个**：京东 query 里的 `t` 是 `[签名用的 t, 新生成的毫秒时间戳]`
  两元素数组。

## 十、第九坑：反调试与"每天/每次都在变"

- **门禁式反调试**：问卷星 `abcd2/abcd4/abcd5` 开头 `if(!abcdx()) return;` —— 命中即让结果变
  `undefined`/空值（**静默**）。调试时可用 `vj → vm` 这类换路径的方式绕开 debug 分支。
- **文件名/内容每日变**：BOSS 直聘的 `0f35c990.js` **每天 0–1 点变一次**；拉勾的混淆 JS
  **文件名与内容每次都变**（替换文件名会让页面一直 loading）。**脚本里禁止硬编码这些名字。**
- **执行时间检测**：BOSS 用 `window['s']` 记录脚本开始执行时间，长时间断点逆向后
  "结果会变，甚至长度都不是固定的"。
- **接口强校验**：美团部分接口**请求几次后强校验**；羊了个羊加入 `Version` 后原思路失效。

## 十一、排查顺序（照这个顺序走，不要跳）

1. **量四件事**（§一）→ 确定是否真的需要逆算法。
2. **取真值样本**：一次成功的请求 + 完整的待签串（不是只看参数名）。**没有真值样本不要开始写实现。**
3. **判魔改**（§二）：标准库先跑一遍，对不上就去统计归纳表/密钥。
4. **钉串的组成**（§三/§四/§九）：分隔符、顺序、盐值位置、时间戳单位、空值处理、大小写。
5. **钉环境白名单**（§五）：只补白名单里的字段。
6. **钉 token 来源**（§七）：对比抓包前缀，确认是远程下发还是本地生成。
7. **端到端对拍**：本地生成值 == 抓包真值（逐字节），再做连续多次采集。

## 十二、本项目反复出现的一类"无声缺陷"

上面绝大多数坑的 `symptom_if_wrong` 都是**"没有明确报错"**：403、校验不过、乱码、
`undefined`、长度变了、能过关但不计数。**因此本簇的验收标准不能是"跑通了"，只能是
"与抓包真值逐字节相同"** —— 见 `references/blueprint-schema.md` 末尾关于 `--selftest`
必须具备**失败分支**的要求。
