# 筛选口径设计（三层 + 两张名单）

## 为什么不能只写一条正则

论坛帖子量大、噪声高。单条正则要么太松（捞出大量无关帖，抓取成本高），
要么太紧（静默丢掉真阳性，且你永远不知道）。实证：一条「NOTWEB 反例正则」里
集合了 `刷课|签到|镜像|游戏|教材` 等词，本意是排除垃圾帖，结果把标题明写
**「[Web逆向] XX 刷课分析」**、**「XX 小程序逆向及每日签到」** 的真阳性帖全杀了 —— 38 条潜在误杀里约 10 条是真阳性。

⇒ 正确做法：**多层串联 + 可审计的例外名单**。

## 三层结构

```
第一层  版块白名单（粗筛）
   只保留技术版块，直接排除 悬赏问答区 / 站务处理 / 水漫金山 / 各「讨论求助区」/ 移动安全区 …
   注意：forum 可能为空（搜索结果常无版块字段）→ 空 forum 应放行，不能当失败丢弃。

第二层  标题强特征正则 STRONG（细筛）
   目标领域的强特征词，例（Web 逆向）：
     js逆向|web逆向|javascript|jsvmp|补环境|环境检测|ast|混淆|反混淆|控制流|平坦化|
     滑块|验证码|captcha|点选|加密参数|签名算法|算法还原|wasm|反爬|反调试|插桩|指纹|
     webpack|protobuf|瑞数|极验|顶象|易盾|数美|akamai|cloudflare|h5st|bogus|acw_sc|zp_stoken

第三层  标题反例正则 NOTWEB（排非目标领域）
   安卓|android|apk|so|dex|native|脱壳|加固|ios|手游|外挂|木马|勒索|x64dbg|ida|
   frida|unidbg|flutter|ollvm|d-810|de4dot|vmp壳|dll|shellcode|……
   ⚠️ 这一层最容易误杀，因为反例词会出现在真阳性标题里（刷课/签到/镜像/游戏/教材/工具）。
```

## 两张人工名单（口径的可审计修正层）

| 名单 | 语义 | 何时加 |
| --- | --- | --- |
| `ALLOW_EXTRA` | 强制保留（越过 NOTWEB，甚至越过 STRONG） | 审计发现「STRONG 命中但被 NOTWEB 拦下」的真阳性 |
| `BLOCK_EXTRA` | 强制排除 | 审计发现「标题像 web，实为 native/桌面端/运维/纯教程」 |

**关键实现细节（血泪）**：

```python
if tid in ALLOW_EXTRA:
    return bool(title.strip())      # ← 只要求标题非空，不要再 and STRONG.search(title)
```

若白名单分支还要求 `STRONG.search(title)`，长尾标题（「参数加密」「逆向解析」「签名服务」）
会被二次拦下 —— 表现为**「加了白名单却不生效」**，完全静默。
加完名单**必须重跑一次增量统计校验**。

## 另一类偏差：STRONG 漏长尾

正则子串是精确匹配，长尾标题形态多变：

| 标题 | STRONG 里的词 | 是否命中 |
| --- | --- | --- |
| 某东 h5st 4.0 加密**参数**逆向 | 加密参数 | ✅ |
| 某东 5.2 第8段**参数加密**逆向解析 | 加密参数 | ❌ 词序反了 |
| 某猫网站 js 数据接口请求**参数加密** | 加密参数 | ❌ |

⇒ 这类只能靠 `audit_miss3` 式审计（「版块白名单内但 STRONG 未命中」）捞出来，
再显式进 `ALLOW_EXTRA`。**不要为了救个案把 STRONG 改得越来越宽**，那会引入噪声。

## 增量策略

```
delta = 本轮候选数 − 已归档数
```

- `delta` 逐轮下降是正常的；降到个位数且审计三张表都接近空 → 该主题已近饱和。
- 提高 `delta` 的手段只有两个：**堆新关键词**（扩大分母）、**修口径**（提高召回）。
- 修口径的收益往往高于堆词：本轮 41 篇里有 11 篇是靠修口径捞回的（占 27%）。

## 第四层：正文级复核门槛（当候选池来自审计 C/E 表时必用）

`STRONG` 是**标题级**正则，审计 C/E 表捞回的都是「标题不含 STRONG token」的帖子。当这类候选达到几百篇时，
**标题级信息已经用尽，必须靠正文**；而正文复核的第一版打分若把 `接口 / 参数 / 抓包 / token` 这类泛词算正分，
榜单会被**通用爬虫教程**占满（美女图 / scrapy 爬 IP / 12306 / 数据可视化），真阳性被埋在中后段。

**硬门槛（先做）**：正文必须命中 ≥1 条核心逆向信号 ——
`加密|解密|签名|sign|验签|补环境|jsdom|环境检测|debugger|ast|babel|反混淆|webpack|扣代码|jsvmp|字节码|`
`插桩|风控|反爬|指纹|akamai|cloudflare|瑞数|加速乐|wzsl|滑块|验证码|captcha|点选|极验|参数加密|参数逆向|`
`参数分析|加密入口|算法还原|hook|混淆`
→ 不命中直接淘汰（实测 548 → 196）。

**加权（后做）**：核心信号 4~5 分（补环境 / AST / 扣代码 / jsvmp / 风控），泛词（token / 接口 / header）1 分；
通用爬虫教程（`美女|套图|壁纸`、`爬虫入门|保姆级|小白|学习笔记`、`数据可视化|matplotlib|词云`、`12306|抢票`）与
native/移动端（`注册机|脱壳|frida|x64dbg|ida|jadx|unidbg|apk|安卓|smali|ollvm`）计**负分**。

**判定速记**：*「有没有分析/还原某段 JS 或某层防护」才是 web 逆向；
「用 requests / scrapy / selenium 把数据取回来」不是* —— 后者哪怕带 `token / sign / cookie` 字段也算噪声。

复核结论必须固化成 `<ALLOW_EXTRA<N>>` / `<BLOCK_EXTRA<N>>`：白名单进候选落盘，
**噪声也一定要入库**，否则下一轮粗筛会把同一批几百篇正文再抓一遍（单轮白烧约 40 min）。

## 第五层：判定层的「宽进 / 窄出」原则（第三十轮实测）

判定层（决定「是否进候选」）与排除层（决定「是否剔除」）要用**相反的严格度**：

- **判定层要宽**：`HARD ∧ WEBCTX` 这种「必须同时满足两个词表」的写法会**整类漏掉**中英混排或纯动作词标题
  —— 实测漏掉 `jQuery Hook`（`jQuery` 不含 `js` 子串）、`文心一言绕过无限debugger`（无任何 WEBCTX 词）、
  `通过浏览器自带API 捕获常见视频流数据的userscript`（词表未收 `userscript`）。
  ⇒ 补一个 **`WEBHARD`** 单层豁免（web 专属强逆向信号，命中即视为已有 web 上下文）：
  `hook|debugger|反调试|补环境|jsdom|execjs|扣代码|扣js|webpack|反混淆|jsvmp|油猴|userscript|crx|
   浏览器扩展|滑块|字体|canvas|m3u8|hls|直链|参数逆向|cookie|视频流|mse`
  判定式：`HARD ∧ (WEBCTX ∨ WEBHARD)`，实测 T0 候选 19 → 40，多出的 21 条捞出 **5 篇**真阳性。
  （同族坑：中英混排不要加 `\b`，见坑 51。）
- **排除层要窄**：`工具|自动|助手|练手|新手` 这类过泛词**不得单独判死**（会误杀《顺便解一个加密练手》
  这类真阳性，见坑 79）；同理 `T8` 的标题级黑名单也不能并入全局 NOISE。

## 第六层：主题通道必须配「正文级判据」才成立（第三十轮实测）

「网盘/文件站直链」这类主题**标题级信号与真阳性严重错位**：2012~2018 年的
《百度/城通/华为/115 网盘地址解析工具》标题里 `网盘|解析|直链|获取真实地址` 全中，
但**95% 的正文只有截图 + 附件**（无任何算法/接口细节）。实测 T8 85 候选 → 仅 10 篇可用。

**正文级判据**（可直接复用）：

- ✅ **收**：正文含**代码块**（`execjs` / curl / PHP / Python / C# / UserScript）**或**接口链路细节
  （`api/streaming?path=`、`v2/file/create`、`ap/login/anonymous`、`bdstoken`、`shareid` 拼接、
  域名/host 替换如 `d.pcs.baidu.com` → `yqall02.baidupcs.com`）。
- ❌ **不收**：只有截图 + 附件/网盘链接的 exe 工具帖（常伴「求评分」「回复中奖」句式）。

⇒ **结论**：标题级通道的边际收益已归零；当某主题的候选命中率高但正文产出率 <15% 时，
应把该主题**从「标题级通道」升级为「正文级通道」**，而不是继续加大标题词表。

## 第七层：通道结项判据（第三十轮）

一个批次通道可判「结项」的三个信号（同时满足）：

1. **全量已看过**：候选池 100% 经过逐条正文复核（不是标题级筛选后的子集）；
2. **命中率 <3%**：如失联池 334 条全量 → 6 篇（1.8%）；
3. **分数分段无新形态**：低分段（score 0~2）样本 50 条抽看后无新形态
   （实测 score=1 段清一色「python 爬取某音乐/视频/小说」）。

结项后**不再投预算**，只保留「固定体检」（G 表黑名单体检 + 三集合理账）。


## 第八层：「系列名差集」通道（第三十一轮新增，必跑）

标题级正则（含 `STRONG`）会因 `\b` 遇 CJK 不匹配而**整系列漏掉**（见 SKILL 坑 84）。
因此每轮固定做一次**系列名差集**：

1. 对**全量池**的标题按系列名分组：
   `其实很简单|小白讲解|大讲堂|第\d+[讲课篇部章]|之\d+|系列|连载|（一）(二)(三)|合集|教程\d+`
2. 每组与**已归档集合**（`docs/references` 的 ID）做差集；
3. 差集里**标题同时含 web 逆向信号**的 → 直接进候选（**不必再抓正文即可判定为高价值**，因为同系列已归档部分已证明主题）。

第 31 轮实测：`《JavaScript AST其实很简单》` 5 篇全漏、`小白讲解` 系列漏 6 篇（01/04/05/07/08/10）
—— 一次核对即捞回 **11 篇**，占本轮定稿的 48%。

## 第九层：黑名单（G 表）正文级体检（第三十一轮新增，降频跑）

标题级黑名单会**随时间累积系统性偏差**（坑 76 的 `2017001`、坑 85 的 `2046628` 都是同一形态）。

* **判据按正文**：正文含**可复用技术内容**（代码块 ≥2 个围栏 + 多个逆向核心信号）即 RESCUE；
  **标题是求助帖/提问帖不影响判定** —— 只要正文含完整分析过程/代码/接口链路。
* **成本≈0**（正文全在本地 `bodies*`），但产出率极低（第 31 轮 3381 → 3，**0.09%**）
  ⇒ **每 3~5 轮跑一次**，或 BLOCK 名单新增 ≥100 条时跑。
* 排除层要窄：`工具|自动|助手|练手|新手` 这类泛词**不得单独判死**（坑 79）。

### 第八层补充：反向 n-gram 差集（第三十二轮新增，与结构法互为正交，**必跑**）

结构法（第八层原方案）只覆盖「带括号 / 带编号」的系列名，会整条漏掉：
引号书名、方括号系列名、**只在续篇里才出现的系列名**（见 SKILL 坑 88）。

```
# 两种模式一起跑（推荐）：从「已归档标题」抽 n-gram 当系列名，再到全量池找未归档同族帖
python scripts/series-diff.py --mode both     --pool artifacts/<platform>-fetchN/pool_vN.json     --ref <语料目录>     --out artifacts/<platform>-fetchN/series_gap
#   → 产出 series_gap_struct.txt（结构法）/ series_gap_ngram.txt（反向法）

# 阈值（坑 91，别乱调）：--min-arch 2 --max-arch 6 --min-len 5
# 只看「有归档成员且还有空缺」的组（**命中率最高的子集**，坑 90）：
python scripts/series-diff.py --mode ngram --pool ... --ref ... --only-archived-gap
```

判据与阈值（坑 90/91）：

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 系列名候选来源 | **已归档标题**（反向）| 结构法用池内标题 |
| 候选出现篇数 | 归档标题中 **2~6 篇** | <2 孤例；>6 通用词 |
| 候选长度 | **≥5** | 4 字短词噪声大 |
| 切分方式 | CJK 连续串取 4~8 字 n-gram；拉丁取**整词** | 禁字符级 n-gram |
| 组级闸门 | 前缀是发帖标签词（原创/求助/开源/更新/转载/源码…）→ 跳过；组内版本号密集 → 跳过 | 坑 89 |
| 排序 | 按 **已有归档成员数** 降序，**不按空缺数** | 坑 90 |

第 32 轮实测：结构法 3899 组 → 285 候选 → 8 篇；反向法 + 人工精投 22 条 → 17 篇；
**两个完整系列被补全**（`Fiddler为所欲为` 补 ① ② ③ ⑤，`消灭病毒` 补 4 篇）。

### 第八层补充②：反向通道的「历史黑名单交叉」闸门（第三十三轮新增，**每轮必做**）

系列名差集 / 反向 n-gram / 家族扫描都是**从已归档标题反推系列名、再去全量池找同族帖**，
而全量池里混着大量**历轮已判死并写进 `BLOCK_EXTRA*` 的帖子** —— 反向通道会把它们原样再捞回来。

```
候选 = 反向通道产出 − (historical BLOCK_EXTRA* 并集)
```

第 33 轮实测：1058 条候选 ∩ 并集（3761 条）= **324 条（31%）**，
这部分历轮已抓过正文、看过、判过 ⇒ 不做交叉就白烧 1/3 抓取成本。
**被减掉的部分不再抓正文**；剩下的「从未复核」子集才叠加标题 web 信号继续走。

### 第八层补充③：`--only-archived-gap` 的语义与结论（第三十三轮）

`--only-archived-gap` 此前是**只声明未实现的空参数**（`mode_struct` 收了 `only_gap` 却没用）。
落地方式：对**已归档标题**也跑一遍 `struct_keys` 得到「已有归档成员的系列名」集合，据此过滤候选组。

| 口径 | 结构法候选 | 说明 |
| --- | --- | --- |
| 不带 gap 过滤 | **285 条**（266 组） | 第 32 轮口径 |
| 带 gap 过滤 | **86 条**（4 组） | 78 条是已知「伪系列」油猴标签组 |

⇒ **「有归档成员的系列组」已被第 31~33 轮吃干**，系列通道降级为「顺带跑一次」，不再单列为主通道。

### 第十层：真实增量来源的判别速记（三轮收敛）

| 通道 | 产出率 | 处置 |

⇒ 第 34 轮的经验修正：长尾期不应继续**向外**加通道（全关），而应**向内**看「已归档语料自己引用了谁」——
见第十一层，这是第 31~34 轮里命中率唯一还在 20% 量级的通道。

**两个向内通道互补**：互链 = 「谁引用过它」，作者 = 「谁写的它」。局限也很清楚：
作者维度必须走浏览器，**会被 WAF 掐断，且连带封掉 RPC**（坑 97）。

## 第十一层：正文互链差集（第三十四轮新增，**零网络成本，建议每轮第一个跑**）

**动机**：长尾期「向外找新帖」的通道全部关闭/饱和后，还剩一个**向内**的视角 ——
**已归档文章自己引用了哪些同主题老帖**（`https://www.52pojie.cn/thread-<id>-1-1.html`，常写作"详见 XX"）。

**为什么它是真通道**：
1. 被引用帖**不在版块时间序的采样深度内**（老帖翻不到底）→ 版块枚举漏；
2. 标题未必含任何关键词 → 关键词通道漏；
3. 但**主题相关性已被同领域作者人工挑过一遍** → 天然高信噪比。

**实现**（技能自带 `scripts/cite-scan.py`）：
```bash
python scripts/cite-scan.py --ref docs/references --root . \
       --pool artifacts/<platform>-fetch<N>/pool_v<N>.json \
       --out artifacts/<platform>-fetch<N>/cite<N>.json
# 净候选 = 被引用ID − 已归档ID − BLOCK并集
```

**实测（52pojie 第三十四轮）**：

| 口径 | 数量 |
| --- | --- |
| 已归档文件 | 1128 |
| 唯一被引用帖 | 184 |
| 未归档 | 91 |
| 净候选（减黑名单） | **72**（其中 22 条**不在全量池**） |
| 定稿 | **15**（命中率 ~21%） |

**两个必须记住的口径**：
- ❌ **来源不要扩大**：换成「全部已抓正文」（`bodies*`，6139 文件）后候选 575，但过标题 web 信号**只多 19 条且全是工具帖**
  （`bodies*` 里 80% 是历轮已判噪声）⇒ **只扫「已归档正文」**。
- ✅ **优先看 `cited_by` 次数高的**：被 3~7 篇不同归档文件引用过的帖（如 `1940562` CCTV cbox 解密被引 3 次、
  `661779`/`1695141` 被引 7 次）几乎必然是主题正相关的；被引 1 次的才是长尾。
- ⚠️ **池外帖没有标题**：`in_pool=false` 的条目在池里查不到标题，**只能直接抓正文**（抓回来正文首行 `# ` 就是标题）
  —— 这也是本通道能捞到「历轮全池都没覆盖的老帖」的原因。

**三种链接形态的实测（52pojie 第三十五轮）**：

| 形态 | 正则 | 唯一被引用 | 未归档 | 净候选 | 处置 |
| --- | --- | --- | --- | --- | --- |
| `thread-<id>` | `52pojie\.cn/thread-(\d{5,})` | 190 | 80 | **17** | ✅ 主力（`cite-scan.py` 默认） |
| `?mod=viewthread&tid=<id>` / `tid=<id>` | `tid=(\d{5,})` | 30 | 17 | **12** | ✅ 可用，但产出偏「下载器/调试工具」帖 |

⇒ 第 35 轮净候选从 72 掉到 17，**不是通道失效，而是黑名单闸门在起作用**：
上一轮的 72 条里 15 条已归档、82 条已写进 `BLOCK_EXTRA34.json`（坑 92 的固定前置动作）。
**任何「从全量池反向捞候选」的通道，都要先减 `BLOCK_EXTRA*` 并集**，否则每轮都会把早判帖重抓一遍。

## 第十二层：作者维度（第三十五轮新增 —— 命中率 ~45%，历轮最高；先读坑 97/99 再动）

**动机**：长尾期「向外找新帖」的通道全关后，还剩**第四个视角：作者** ——
「**能写出 web 逆向长文的作者，其空间里的其他主题大概率同领域**」，且这些帖**标题不含关键词、也不在版块采样深度内**
（与坑 84「系列帖从未进过候选池」同源）。

**数据来源**：归档正文头部 `> **作者**: X` → 621 位唯一作者 → 取 **≥2 篇归档**的 170 位（= 已被证明的同领域写手）。

**实现**（技能自带 `scripts/author-scan.py`）：`home.php?mod=space&username=<GBK>` → 取 uid →
`home.php?mod=space&uid=<uid>&do=thread&type=thread&page=N` → 选择器 `#ct .mn a[href*="thread-"]`。

**实测战绩（52pojie 第三十五轮，跑通后）**：

| 口径 | 数量 |
| --- | --- |
| 扫过的作者（≥2 篇归档里的前 110 位） | 110 |
| 抓到的主题 | 2278 |
| 未归档 ∧ 未黑名单 | 800+ |
| 过标题门禁（web 信号 ∧ ¬native/工具/教程） | **149** |
| 抓正文 | 40（ok 35 / 缓存 2 / 已删或受限 3） |
| 定稿 | **18**（命中率 ~45%，**历轮最高**） |

**淘汰口径（本轮实测，必须按正文判、不按标题判）**：
① 移动端/native（apk 去广告、app 抓包、某 TV 客户端 QUIC+jce、改注册表 MAC）；
② 工具/成品发布（易语言抖音下载器）；③ 纯加解密脚本与爬虫教程（AES-ECB 批量解密、"js 未动"的 execjs 调用）。

**与第十一层的关系**：两者**互补且盲区不同** —— 互链找「被同领域作者引用过」的老帖，
作者维度找「同一位作者写过、但标题不含任何关键词」的帖（本轮 149 条候选里绝大多数是**全量池外**）。
⇒ 两者都应固定跑，但**作者维度必须排在所有 RPC 动作之后**（坑 97）。

**⛔ 硬约束（第三十五轮实测踩到）**：
1. **浏览器侧动作必须排在所有 RPC 侧动作之后** —— 第三十五轮在 RPC 抓取之后跑该通道，
   连发 ~100 次同源 XHR 后触发网宿滑块 WAF（`wzws-waf-cgi` → `waf_slider_verify.html`），
   **并且是 IP 级封禁：`hubcli Thread` 立刻返回 `[]`、`content` 返回空壳**（整轮抓取瘫痪）。
2. 节奏 **≥6 s/次**，每 20 次**导航到站点首页**刷新 WAF cookie（导航会执行挑战页 JS，同步 XHR 不会）。
3. 一旦响应含 `wzws-waf-cgi` / `waf_slider_verify` / 标题为空 ⇒ **立即整轮停止**。
4. 解析细节：`hubcli browser eval` **不 await Promise**（必须同步 XHR）；`?username=` 要 **GBK 转义**（坑 27 同源）。


**尚未覆盖（下轮可补，成本极低）**：
① ✅ **已做（第三十六轮）**：`forum.php?mod=viewthread&tid=<id>` 形态（可跑，但产出偏工具帖）；
② ❌ **已判废（坑 98）**：正文里**裸写的纯数字 ID**（如"参考 1234567"）—— 需配合「该数字确实在池里」以控制误命中；
③ 外站引用（`github.com/...`）—— 价值在工具链，不在帖。

## 第十三层：作者 uid 维度 + 覆盖度审计（第三十六轮新增 —— 可用，但**噪声率高一个数量级**）

**它是什么**：第十二层（name 维度）的补充视角 —— 不按「作者名」进空间，而是从**互链/引用关系**里
抽出暴露的作者 **uid**，直接 `home.php?mod=space&uid=<uid>&do=thread&type=thread&page=N` 翻空间主题。

**两档先验质量差很多（第三十六轮实测）**：

| 维度 | 输入的先验 | 候选 | 定稿 | 备注 |
| --- | --- | --- | --- | --- |
| **name**（第十二层） | 「**写出过长文**的已知作者」（≥2 篇归档） | 149 | 18 | 候选命中 ~12% |
| **uid**（本层） | 只是「**被引用过**」，与「会写逆向长文」弱相关 | +41 | +2 | 新增候选里 ~95% 是提问/求助/浏览器使用/工具发布 |

**结论与用法**：
1. **可以做，但门禁必须更严**：正文级要求「含代码块 ∧ 有逆向动作词」，**不看标题**；
2. **两档候选不要混进同一张清单**（混表会让「候选命中率」这个跨轮指标失真）；
3. 它的**真实价值在「补覆盖」而非「补产出」**：本轮它的主要贡献是把候选池从 149 扩到 190，
   真正捞到的 web 逆向帖只有 2 篇（`1910333` 盐选字体反爬是互链给的、`747271` 图片站接口是 name 给的）。

**覆盖度审计（建议每轮开跑前先算一次）**：见 `scripts/author-coverage.py`。

## 第十四层：续跑轮的「集合差」口径（第三十七轮新增 —— **每轮开工第一个动作**）

**问题**：定时任务被打断后（坑 100），下一轮接手时拿到的候选清单是**跨轮累积**的，
里面很大一部分正文**早就抓在本地**（`bodies<N-1>/` 或 `bodies<N>/`），只是没落盘。
若按「候选数」估算工作量与产出率，会得到严重虚高的数字。

第三十七轮实测：`filter_author37.py` 输出 **229 候选**，其中 **156 篇正文已在 `bodies37/`**
⇒ 真正还需要发请求的只有 **77 条**（虚高 ~19 倍）。

```bash
python - <<'PY'
import os
need = {l.split('\t')[0] for l in open('need_author37.txt', encoding='utf-8') if l.strip()}
have = {f[:-3] for f in os.listdir('bodies37')}
print('候选 %d | 本地已有 %d | 待抓 %d' % (len(need), len(have), len(need - have)))
PY
```

**三条纪律**：
1. **开工先算差**（`need − bodies*`）再决定发不发请求；
2. **汇报口径分两栏**：`候选` 与 `本轮新增抓取` 分开写，**不要合并**（否则跨轮产出率指标失真）；
3. `have` 那部分**零成本**：正文就在本地，直接人工判读 ——
   第三十七轮的 12 篇定稿**全部**出自「本地已有」的那 156 篇，新增请求只用来补 12 条边角候选（命中 0）。

**与第十三层的关系**：第十三层给了「怎么找候选」，本层给「**找到之后先减掉本地已有的**」。
两者串起来才是完整的续跑口径。

## 第十五层：G 表（黑名单）体检的「两段式」+ 全通道见底的确认口径（第三十八轮新增）

### A. G 表体检：先标题级收窄，再抓正文

历轮 G 表（第九层）在**零散样本**或**全量 3381 条**上做，成本高、结论重复。第三十八轮固化为**两段式**：

```
① 并集历轮黑名单（block-union.py）          本轮 4238 条 / 24 文件
② × 全量池标题 × 强 web 信号 ∧ ¬native/移动/求助/课程    → 收窄到 85 条（2%）
③ 只对 85 条抓正文复核
```

**第三十八轮实测结论**：78 条为真噪声；另 2 条「高信号」也都**不是误杀**而是**正文已毁** ——
`1994034`（某东 h5st 5.0）作者被警告后自删（只剩“被警告 再见”）、
`1756698`（JS逆向百例·加速乐）被作者截断成 462 B（重抓逐字复现 ⇒ 上游如此）。
⇒ **黑名单里凡「标题极像真阳性」的，先怀疑「正文已删/已截断」，不要先怀疑口径误杀**；
G 表**每 3~5 轮一次**、且**永远先标题级收窄**（全量正文级 = ~50× 成本换同一结论）。

### B. 全通道见底的判据（什么时候该降频）

当**同一条平台**出现下列**同时成立**时，可把轮次频率降到 **每 2~3 天一次**，
并把「找新帖」的预算让位给「口径审计 / 语料体检」：

1. **结构通道全 0**：`Thread` 逐页池外新帖里 web 逆向 = 0，**连续 ≥5 轮**（本轮为第 3~38 轮同一结论）；
2. **零成本通道枯竭**：正文互链净候选 ≤ 5、系列名差集（struct+ngram）净候选全为工具/求助；
3. **作者维度先验转负**：门禁候选（十位数）→ 定稿 **0**，且连续 ≥2 轮（第三十七轮命中 0 / 本轮命中 0）；
4. **孤儿正文见底**：`bodies*` 缓存里「未归档 ∧ 未黑名单」的强信号标题 ≤ 10 条；
5. **G 表结论稳定**：连续 2 轮「无系统性误杀」。

**注意**：判「见底」**不等于**停止 —— 第 4/5 条仍是**零成本**动作，保留为每轮固定体检；
停的只是「**为找新帖而发大量请求**」这件事。
⚠️ 见底轮**不要把产出数字硬凑上去**：本轮六条通道合计只产 8 篇（其中 7 篇来自全池长尾），
如实记录「个位数」本身就是有价值的口径信号（说明该平台 web 逆向语料已近饱和）。
