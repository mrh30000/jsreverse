# 筛选口径设计（三层 + 两张名单）

## 为什么不能只写一条正则

论坛帖子量大、噪声高。单条正则要么太松（捞出大量无关帖，抓取成本高），
要么太紧（静默丢掉真阳性，且你永远不知道）。实证：一条「NOTWEB 反例正则」里
集合了 `刷课|签到|镜像|游戏|教材` 等词，本意是排除垃圾帖，结果把标题明写
**「[Web逆向] XX 刷课分析」**、**「XX 小程序逆向及每日签到」** 的真阳性帖全杀了 —— 38 条潜在误杀里约 10 条是真阳性。

⇒ 正确做法：**多层串联 + 可审计的例外名单**。

## 三层结构

```
第一层  版块白名单（粗筛）
   只保留技术版块，直接排除 悬赏问答区 / 站务处理 / 水漫金山 / 各「讨论求助区」/ 移动安全区 …
   注意：forum 可能为空（搜索结果常无版块字段）→ 空 forum 应放行，不能当失败丢弃。

第二层  标题强特征正则 STRONG（细筛）
   目标领域的强特征词，例（Web 逆向）：
     js逆向|web逆向|javascript|jsvmp|补环境|环境检测|ast|混淆|反混淆|控制流|平坦化|
     滑块|验证码|captcha|点选|加密参数|签名算法|算法还原|wasm|反爬|反调试|插桩|指纹|
     webpack|protobuf|瑞数|极验|顶象|易盾|数美|akamai|cloudflare|h5st|bogus|acw_sc|zp_stoken

第三层  标题反例正则 NOTWEB（排非目标领域）
   安卓|android|apk|so|dex|native|脱壳|加固|ios|手游|外挂|木马|勒索|x64dbg|ida|
   frida|unidbg|flutter|ollvm|d-810|de4dot|vmp壳|dll|shellcode|……
   ⚠️ 这一层最容易误杀，因为反例词会出现在真阳性标题里（刷课/签到/镜像/游戏/教材/工具）。
```

## 两张人工名单（口径的可审计修正层）

| 名单 | 语义 | 何时加 |
| --- | --- | --- |
| `ALLOW_EXTRA` | 强制保留（越过 NOTWEB，甚至越过 STRONG） | 审计发现「STRONG 命中但被 NOTWEB 拦下」的真阳性 |
| `BLOCK_EXTRA` | 强制排除 | 审计发现「标题像 web，实为 native/桌面端/运维/纯教程」 |

**关键实现细节（血泪）**：

```python
if tid in ALLOW_EXTRA:
    return bool(title.strip())      # ← 只要求标题非空，不要再 and STRONG.search(title)
```

若白名单分支还要求 `STRONG.search(title)`，长尾标题（「参数加密」「逆向解析」「签名服务」）
会被二次拦下 —— 表现为**「加了白名单却不生效」**，完全静默。
加完名单**必须重跑一次增量统计校验**。

## 另一类偏差：STRONG 漏长尾

正则子串是精确匹配，长尾标题形态多变：

| 标题 | STRONG 里的词 | 是否命中 |
| --- | --- | --- |
| 某东 h5st 4.0 加密**参数**逆向 | 加密参数 | ✅ |
| 某东 5.2 第8段**参数加密**逆向解析 | 加密参数 | ❌ 词序反了 |
| 某猫网站 js 数据接口请求**参数加密** | 加密参数 | ❌ |

⇒ 这类只能靠 `audit_miss3` 式审计（「版块白名单内但 STRONG 未命中」）捞出来，
再显式进 `ALLOW_EXTRA`。**不要为了救个案把 STRONG 改得越来越宽**，那会引入噪声。

## 增量策略

```
delta = 本轮候选数 − 已归档数
```

- `delta` 逐轮下降是正常的；降到个位数且审计三张表都接近空 → 该主题已近饱和。
- 提高 `delta` 的手段只有两个：**堆新关键词**（扩大分母）、**修口径**（提高召回）。
- 修口径的收益往往高于堆词：本轮 41 篇里有 11 篇是靠修口径捞回的（占 27%）。

## 第四层：正文级复核门槛（当候选池来自审计 C/E 表时必用）

`STRONG` 是**标题级**正则，审计 C/E 表捞回的都是「标题不含 STRONG token」的帖子。当这类候选达到几百篇时，
**标题级信息已经用尽，必须靠正文**；而正文复核的第一版打分若把 `接口 / 参数 / 抓包 / token` 这类泛词算正分，
榜单会被**通用爬虫教程**占满（美女图 / scrapy 爬 IP / 12306 / 数据可视化），真阳性被埋在中后段。

**硬门槛（先做）**：正文必须命中 ≥1 条核心逆向信号 ——
`加密|解密|签名|sign|验签|补环境|jsdom|环境检测|debugger|ast|babel|反混淆|webpack|扣代码|jsvmp|字节码|`
`插桩|风控|反爬|指纹|akamai|cloudflare|瑞数|加速乐|wzsl|滑块|验证码|captcha|点选|极验|参数加密|参数逆向|`
`参数分析|加密入口|算法还原|hook|混淆`
→ 不命中直接淘汰（实测 548 → 196）。

**加权（后做）**：核心信号 4~5 分（补环境 / AST / 扣代码 / jsvmp / 风控），泛词（token / 接口 / header）1 分；
通用爬虫教程（`美女|套图|壁纸`、`爬虫入门|保姆级|小白|学习笔记`、`数据可视化|matplotlib|词云`、`12306|抢票`）与
native/移动端（`注册机|脱壳|frida|x64dbg|ida|jadx|unidbg|apk|安卓|smali|ollvm`）计**负分**。

**判定速记**：*「有没有分析/还原某段 JS 或某层防护」才是 web 逆向；
「用 requests / scrapy / selenium 把数据取回来」不是* —— 后者哪怕带 `token / sign / cookie` 字段也算噪声。

复核结论必须固化成 `<ALLOW_EXTRA<N>>` / `<BLOCK_EXTRA<N>>`：白名单进候选落盘，
**噪声也一定要入库**，否则下一轮粗筛会把同一批几百篇正文再抓一遍（单轮白烧约 40 min）。

## 第五层：判定层的「宽进 / 窄出」原则（第三十轮实测）

判定层（决定「是否进候选」）与排除层（决定「是否剔除」）要用**相反的严格度**：

- **判定层要宽**：`HARD ∧ WEBCTX` 这种「必须同时满足两个词表」的写法会**整类漏掉**中英混排或纯动作词标题
  —— 实测漏掉 `jQuery Hook`（`jQuery` 不含 `js` 子串）、`文心一言绕过无限debugger`（无任何 WEBCTX 词）、
  `通过浏览器自带API 捕获常见视频流数据的userscript`（词表未收 `userscript`）。
  ⇒ 补一个 **`WEBHARD`** 单层豁免（web 专属强逆向信号，命中即视为已有 web 上下文）：
  `hook|debugger|反调试|补环境|jsdom|execjs|扣代码|扣js|webpack|反混淆|jsvmp|油猴|userscript|crx|
   浏览器扩展|滑块|字体|canvas|m3u8|hls|直链|参数逆向|cookie|视频流|mse`
  判定式：`HARD ∧ (WEBCTX ∨ WEBHARD)`，实测 T0 候选 19 → 40，多出的 21 条捞出 **5 篇**真阳性。
  （同族坑：中英混排不要加 `\b`，见坑 51。）
- **排除层要窄**：`工具|自动|助手|练手|新手` 这类过泛词**不得单独判死**（会误杀《顺便解一个加密练手》
  这类真阳性，见坑 79）；同理 `T8` 的标题级黑名单也不能并入全局 NOISE。

## 第六层：主题通道必须配「正文级判据」才成立（第三十轮实测）

「网盘/文件站直链」这类主题**标题级信号与真阳性严重错位**：2012~2018 年的
《百度/城通/华为/115 网盘地址解析工具》标题里 `网盘|解析|直链|获取真实地址` 全中，
但**95% 的正文只有截图 + 附件**（无任何算法/接口细节）。实测 T8 85 候选 → 仅 10 篇可用。

**正文级判据**（可直接复用）：

- ✅ **收**：正文含**代码块**（`execjs` / curl / PHP / Python / C# / UserScript）**或**接口链路细节
  （`api/streaming?path=`、`v2/file/create`、`ap/login/anonymous`、`bdstoken`、`shareid` 拼接、
  域名/host 替换如 `d.pcs.baidu.com` → `yqall02.baidupcs.com`）。
- ❌ **不收**：只有截图 + 附件/网盘链接的 exe 工具帖（常伴「求评分」「回复中奖」句式）。

⇒ **结论**：标题级通道的边际收益已归零；当某主题的候选命中率高但正文产出率 <15% 时，
应把该主题**从「标题级通道」升级为「正文级通道」**，而不是继续加大标题词表。

## 第七层：通道结项判据（第三十轮）

一个批次通道可判「结项」的三个信号（同时满足）：

1. **全量已看过**：候选池 100% 经过逐条正文复核（不是标题级筛选后的子集）；
2. **命中率 <3%**：如失联池 334 条全量 → 6 篇（1.8%）；
3. **分数分段无新形态**：低分段（score 0~2）样本 50 条抽看后无新形态
   （实测 score=1 段清一色「python 爬取某音乐/视频/小说」）。

结项后**不再投预算**，只保留「固定体检」（G 表黑名单体检 + 三集合理账）。


## 第八层：「系列名差集」通道（第三十一轮新增，必跑）

标题级正则（含 `STRONG`）会因 `\b` 遇 CJK 不匹配而**整系列漏掉**（见 SKILL 坑 84）。
因此每轮固定做一次**系列名差集**：

1. 对**全量池**的标题按系列名分组：
   `其实很简单|小白讲解|大讲堂|第\d+[讲课篇部章]|之\d+|系列|连载|（一）(二)(三)|合集|教程\d+`
2. 每组与**已归档集合**（`docs/references` 的 ID）做差集；
3. 差集里**标题同时含 web 逆向信号**的 → 直接进候选（**不必再抓正文即可判定为高价值**，因为同系列已归档部分已证明主题）。

第 31 轮实测：`《JavaScript AST其实很简单》` 5 篇全漏、`小白讲解` 系列漏 6 篇（01/04/05/07/08/10）
—— 一次核对即捞回 **11 篇**，占本轮定稿的 48%。

## 第九层：黑名单（G 表）正文级体检（第三十一轮新增，降频跑）

标题级黑名单会**随时间累积系统性偏差**（坑 76 的 `2017001`、坑 85 的 `2046628` 都是同一形态）。

* **判据按正文**：正文含**可复用技术内容**（代码块 ≥2 个围栏 + 多个逆向核心信号）即 RESCUE；
  **标题是求助帖/提问帖不影响判定** —— 只要正文含完整分析过程/代码/接口链路。
* **成本≈0**（正文全在本地 `bodies*`），但产出率极低（第 31 轮 3381 → 3，**0.09%**）
  ⇒ **每 3~5 轮跑一次**，或 BLOCK 名单新增 ≥100 条时跑。
* 排除层要窄：`工具|自动|助手|练手|新手` 这类泛词**不得单独判死**（坑 79）。
