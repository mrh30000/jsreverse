# 论坛语料批量归档 (Forum Corpus Archival)

把「论坛上散落的领域文章」变成「可检索、可去重、可审计的本地 Markdown 语料库」。

核心不是抓取（抓取是一次性的），而是**筛选口径的可审计性**：口径一旦有系统性偏差，
会静默丢掉一整类真阳性，且下一轮沿用同一口径时你永远发现不了。本技能的重点在审计。

## 适用场景

1. 从 52pojie / 看雪 / 吾爱等论坛按主题（如 Web 逆向）批量沉淀文章到 `docs/references/`。
2. 增量补漏：定时任务第二轮、第三轮执行时如何判断「还能捞到什么」。
3. 已有语料库的口径体检：怀疑漏拣或误杀时怎么定位。

## 工作流（六步）

### 1. 枚举数据源（增量优先，但增量通常近零）

```bash
hubcli <platform> Thread --page 1 --json   # 最新帖列表
hubcli <platform> search --keyword "<关键词>" --limit 40 --json   # ⚠️ 52pojie 中文关键词已失效，见坑 27
```

**先做增量判断**：把最新 Thread 列表与上轮快照按 ID diff。
若新增全是求助/资源帖（论坛常见），**不要再指望 Thread 列表**——增量价值只能来自关键词补漏。

### 2. 关键词扫描（扩大覆盖的唯一手段）

多数论坛搜索**无法翻页**（见坑 1），覆盖面积 = 关键词数量。按维度系统性铺词，不要随机想：

| 维度 | 例（Web 逆向） |
| --- | --- |
| 站点名 | 京东 / 淘宝 / 小红书 / 快手 / bilibili |
| **站点隐称**（易整层遗漏，见坑 20） | 某音 / 某书 / 某东 / 某团 / 某宝 / 某多 / 某手 / 某鱼 / 某滴 |
| 防护厂商 | 顶象 / 易盾 / 数美 / 瑞数 / Akamai / Cloudflare / 加速乐 |
| 厂商隐称 | 某验 / 某数 / 某盾 / 某顿 / 某里 |
| 算法/参数名 | h5st / a_bogus / x-bogus / zp_stoken / acw_sc__v2 / mns |
| 技术手段 | 混淆 / 反混淆 / 控制流平坦化 / AST / wasm / 补环境 / 插桩 |
| 框架/小程序 | uni-app / taro / 抖音小程序 / 支付宝小程序 / wx小程序 |
| 工具链（性价比低，每轮 ≤3 个） | selenium / playwright / puppeteer / mitmproxy |

每词间隔 **> 10s**（论坛限频），失败重试 sleep 也必须 >10s，否则永远失败。

> ⚠️ **52pojie 必读（坑 27~29）**：`hubcli search` 对中文关键词**恒定返回 `[]`**（GBK/UTF-8 字符集不匹配），
> 且 `--limit 40` 会截断热门词。⇒ 一律改用 **浏览器驱动搜索**：
> `python scripts/browser-search.py --kw-file kw.txt --outdir search<N> --tab <52pojie 标签页 id>`。
> 它按 **GBK** 提交关键词、**自动翻页拿全量**（单关键词最多 ~200 条，是历轮 40 条的 5 倍）。

### 3. 合并全量池 + 按 ID 去重

```python
# 多轮结果合并，dict[id] = record，补齐缺失字段（搜索有 forum，Thread 列表没有）
```

### 4. 筛选（三层口径，见 `references/filter-rules.md`）

```
版块白名单  →  标题强特征正则(STRONG)  →  反例正则(NOTWEB)  →  人工白/黑名单
```

### 5. 抓取落盘（自带去重 + 空内容判定 + 断点续跑）

- 目标路径：`<语料目录>/<platform>-<id>-<slug(title)>.md`
- **去重以 ID 为准**，不要用标题（标题会改）。正则要同时兼容历史命名：
  `(?:<platform>-)?(\d{5,})-?.*\.md$`
- **空内容判定**：剥离 `#`/`>`/`---` 行后正文 <200 字符 → 作者已删正文或仅外链，跳过并记录。
- 落盘后**不要立即信任结果**，进入第 6 步。

### 6. 审计与终检（本技能的核心，务必执行）

```bash
python scripts/audit-corpus.py --ref <语料目录> --pool <候选池.json>
```

输出四张表：
- **口径仍会保留（应为 0）**：说明上轮已抓过或抓取失败，非新发现。
- **被 NOTWEB 拦下但 STRONG 命中（潜在误杀）**：**最值得看的一张表**。逐条人工判断，
  确认是真阳性的进 `ALLOW_EXTRA`，确认是反例的进 `BLOCK_EXTRA`。
- **白名单内但 STRONG 未命中（可能漏拣）**：长尾标题形态（如「参数加密」≠「加密参数」）
  会掉在这里，需要显式白名单或扩充 STRONG。
- **forum 为空（Thread 来源）+ 有信号但 STRONG 未命中**：Thread 来源的盲区，
  与坑 7 配套，用来抓回被 `forum` 缺失放过 / 漏掉的帖子。

第七张表（**历史黑名单误杀体检**，可选，见坑 18）：`--block-ids`。把历史人工黑名单命中、
但 STRONG 命中且 NOTWEB 未命中的未归档项列出来 —— 这是唯一能发现「黑名单误杀」的审计，
因为其余各表都把黑名单项当既定结论跳过了。

第五张表（**本轮增量来源体检**，可选）：把本轮新增的 Thread / search 结果集当池，
单独列「未归档 + 有逆向信号 + NOTWEB 未命中」的项，用来判断**本轮新增到底有没有真价值**，
以及是否有被现有口径整类漏掉的形态。用 `--inc-pool <本轮池.json>`（可多个）启用。

第六张表（**口径扩容增量体检**，可选）：当你给 STRONG 加了新 token 时，用
`--strong-new-re <新正则>` 列出「新口径选中、旧口径落选」的项 —— 必须逐条抓正文复核，
因为扩容最常见的失败模式是**假阳性**（如 `参数分析` 命中「汽车配置参数」）与
**黑名单失效**（新分支忘了并集历史黑名单，见坑 15）。

外加 ID 唯一性 / 空文件终检。

## 坑（52pojie 实测）

1. **搜索无法翻页**：`search --page 2` 无 `search_id` 恒返回空。⇒ 覆盖只能靠堆关键词。
   **但 `Thread` 列表可以翻页**：页数不固定（首发轮只探到第 2 页，第四轮第 6 页仍有数据），
   逐页拉到空为止，别沿用上一轮「只有 N 页」的结论。
2. **限频 10 秒**：`search` 间隔 <10s 返回「抱歉，您在 10 秒内只能进行一次搜索」。
   重试 sleep 若 ≤10s，会**永远失败**。用 11~13s。
3. **`[]` 是真实零结果，不是失败**：英文/生僻词（`ja3`、`http2`、`接口签名`）稳定返回 `[]`。
   脚本必须区分「`[]`」与「报错/超时」，否则会把零结果词反复重试并在报告里误报为失败。
4. **反爬环境检查页**：论坛可能弹「浏览器环境检查中」，使 `content`/`search` **全部返回空**。
   解法：`hubcli browser navigate "<论坛首页>" --tab_id <tab>` 过一次即可。
   注意：此现象**不是每次都出现**，先跑一次 `content` 试探，不要盲目预过检。
5. **白名单加了却不生效**：若白名单分支里还要求 `STRONG.search(title)`，
   长尾标题（「参数加密」「逆向解析」）会被二次拦下。白名单分支应只要求标题非空。
   **加完白名单必须重跑一次增量统计校验**，否则这个 bug 完全静默。
6. **两套命名并存**：批量归档用 `<platform>-<id>-<title>.md`，早期人工命名用 `<id>-<slug>.md`。
   去重正则要同时匹配；README 里说明清楚，不要试图统一（会断掉既有引用）。
7. **Thread 列表记录的 `forum` 字段为空**（只有 id/title/url）⇒ 「版块黑名单」对这类帖子**完全失效**，
   移动安全区 / 病毒分析区 的 Android、桌面端帖会被 STRONG 正则收进来。
   合并池时务必用 search 结果回填 forum；回填不到的，只能靠标题人工黑名单兜底。
   **审计必须单独列一张「forum 为空」的表**，否则这类误收永远不会被发现。
8. **后台长任务不要用 `cmd &`**：本仓库 shell 以 `cmd.exe` 为宿主，`&` 起的子进程在父 shell
   退出时会被杀掉（日志停在中途、进程表里只剩 20K 的空壳）。用工具的 `run_in_background`，
   并给抓取脚本加「结果文件已存在则跳过」的断点续跑，避免重启后重跑。
9. **「X参数逆向」类标题会整类漏拣**：STRONG 若只收「加密参数 / 签名算法 / 加密分析」，
   则「某鱼 sign 参数逆向」「某香医生 sign 值参数逆向」「某麦数据参数逆向分析」**全部落空**
   （标题里没有「加密」二字）。⇒ 把 `参数逆向` / `sign` / `参数分析` 直接补进 STRONG，
   或逐条进 `ALLOW_EXTRA`。这是实测中单轮召回缺口最大的一类（一轮 15 篇新增里 13 篇来自此）。
10. **工具类关键词性价比极低**：`fiddler / charles / burpsuite / jadx / unicorn / ollvm /
   frida / rc4 / des加密 / 字符串加密` 召回的基本是**移动端抓包教程、native 工具、加密小工具**，
   真 web 逆向接近 0，反而给筛选引入大量噪声。⇒ 关键词预算优先给「站点名」+
   「参数/签名/接口」+「具体算法名」，工具名最多每轮 2~3 个。
11. **RPC 执行器掉线 ≠ 限频**：报错 `RPC API Error [Code 3001]: no client available` 或
   `当前没有在线的执行器`，表现为**某几个关键词连续 FAILED**（限频的报错文案是「10 秒内只能
   进行一次搜索」，两者要分清）。恢复：`hubcli browser tabs` 找到目标站标签页 id
   → `hubcli browser reload --tab_id <id>` → 重新跑（脚本的断点续跑会把 FAILED 的词重跑，
   但**结果文件已写入的成功词不会重跑**，所以续跑前不必删文件）。
12. **`\b` 对中英混排失效**：`\bast\b` 匹配不到「某数ast+jsdom」（中文字符在 Python `re` 里算
   `\w`，与 `a` 之间没有词边界）。中文标题里的英文技术词一律用**不带 `\b` 的子串匹配**。
13. **WAF 文字验证码会静默污染整个流程，且文案每年在变**（本轮实测，最严重的坑）：
   - 表现一：`content` 返回 `# 访问验证` + `waf_text_verify.html`（历史文案是「环境检查」）。
     **必须把新文案补进反爬判定**，否则「访问验证」会被当成正文落盘（一条 34 字符的假文章）。
   - 表现二（更隐蔽）：`search`/`Thread` **不报错，直接返回 `[]`** —— 与「真实零结果」完全不可区分
     （坑 3）。后台关键词扫描会把**连续多个词记成 ZERO 并落盘**，日志上看不出任何异常。
     ⇒ 抓取/扫描脚本必须加**连续 ZERO 熔断**：池为空且连续 ≥3 个 ZERO 时中止且**不落盘**。
     ⇒ 每轮开工先跑一次 `search` 探活，再启动批量扫描。
   - 恢复：`hubcli browser tabs` 找到 52pojie 标签页 → `hubcli browser activate --tab_id <id>`
     → `screenshot` 截图读验证码（**`--full_page=false` 才截当前视口；不 activate 会截到别的标签页**）
     → `hubcli browser eval` 用 canvas 放大导出原图辅助识别（验证码图片 `naturalWidth` 215×80，
     视口内只显示约 112×34，直接截图几乎看不清）
     → `fill --selector "input.code-input"` + `click --selector "input.code-btn"`。
   - **恢复后必须清掉 WAF 期间误落的 `search*/` 结果文件再续跑**（否则熔断前记的 ZERO 会被永久跳过）。
14. **`search --limit 40` 对热门关键词会截断，是比口径偏差更早的一层盲区**（本轮单轮最大收获）：
   「验证码逆向专栏」「某验 N 代滑块」「某讯滑块」「纯算」这类**整批高价值老帖连候选池都没进**，
   历轮审计 A 表也永远发现不了（A 表只审计「已进池但被口径拦下」的项）。
   ⇒ 热门主题**不要只用宽泛词**（`滑块`/`验证码`），要用**细粒度组合词**拆分覆盖：
   `滑块验证` / `点选` / `参数分析` / `sign参数` / `验签` / `参数校验` / `扣代码` / `纯算` /
   `指令还原` / `字节码` / `opcode` / `报文加密`。本轮靠这一招补回 65 篇。
15. **扩容 STRONG 时，新分支必须先过「历史全部人工黑名单」**：本轮把 `参数分析` 并入 STRONG，
   新分支只 copy 了 `F.BLOCK`（第一轮黑名单），漏掉 `BLOCK_EXTRA3/4/5`，导致 A 表瞬间冒出 99 条
   —— 前几轮明确排除的 native 工具帖全部回流。**黑名单是跨轮累积的，任何新判定分支都要并集全部。**
   另：`参数分析` 会误伤「非加密参数」语境（「汽车之家全系**配置参数**分析」×2）⇒ 需人工黑名单兜。
16. **`python x.py &` 与 `run_in_background` 的落盘竞态**：脚本末尾写汇总文件（`search*_pool.json`）
   发生在最后几个 `print` 之后；**日志出现 `[75/75]` 不等于汇总文件已生成**，此时若立刻跑
   `merge_pool` 会 `skip(missing)`。⇒ 合并前先 `ls` 确认汇总文件存在，或等进程真正退出。

17. **`search` 会返回「假零」（并发 / 后端抖动时静默返回 `[]`），与真实零结果不可区分**（本轮最大教训）：
   - 触发条件：本轮在关键词扫描的**同时**并发跑了 `Thread` 翻页，随后连续出现 ZERO；
     复测（间隔 12s 单独再打一次）发现 `盒马`/`叮咚买菜`/`上汽大众`/`rpc调用`/`验证码逆向` 全部**有结果**，
     其中 `验证码逆向` 一次拿回 **30 条**（含整个「【验证码逆向专栏】」系列）—— 若按旧脚本「首次 `[]` 即落盘」，
     这批帖子会被**永久跳过**（结果文件已存在 → 续跑时被当 done 跳过）。
   - ⇒ **扫描期间禁止任何并发网络请求**（Thread 翻页、content 抓取都要串行）。
   - ⇒ 扫描脚本必须实现**二次确认 ZERO**：首次 `[]` 不算数，隔一个 GAP 复测；仍为 `[]` 才落盘。
   - ⇒ 连续 ZERO 熔断阈值不要设太小：小品牌/长尾站点名（`T3出行`/`曹操出行`/`一汽大众`）
     确为真实零结果，阈值 3 会**误熔断**（本轮两次）；用 6~8，且熔断前先探活一个热门词（如 `京东`）。

18. **人工黑名单会造成「静默误杀」，且任何后续审计都看不见它**（本轮修出一例）：
   - 案例：`2026911` 标题《一个可以练习 webpack 的站》被第四轮按「练习站推荐」拉黑，
     实际正文是 **webpack 扣取 + 请求/响应 SM4 加密 + SM2 签名 + execjs 复现** 的完整实战帖。
   - 为什么历轮审计都发现不了：A/B/C/D/E 表要么把黑名单项当既定结论跳过（A 表用 `keep()` 直接判 False），
     要么按 `id not in BLOCK` 过滤（B 表）。**黑名单是审计的盲区**。
   - ⇒ 每轮审计固定跑一张 **G 表**：`block_ids ∩ (未归档 ∩ STRONG 命中 ∩ NOTWEB 未命中 ∩ 版块合规)`，
     逐条抓正文复核。`scripts/audit-corpus.py --block-ids <id,id|文件>` 已内置。
   - ⇒ 复核结论只有两种：真阳性 → 下一轮 `ALLOW_EXTRA`（`keep` 里白名单判定要放在黑名单之前）；
     确为反例 → 留在黑名单。

19. **裸 `解密 / 加密` 这类泛化 token 会把「加解密编程」整类召回成假阳性**（实测 23 篇）：
   - 现象：`STRONG` 里若含 `解密`、`加密.*分析` 而无共现约束，则**『编程语言区』**里
     `文件内容AES加密解密`、`Golang/Python 常见加解密算法`、`PHP加密解密算法`、`C++自研算法`、
     `recaptcha/Kaptcha 后端接入教程`、以及 **native 侧**（Wechat 密钥内存、LUKS 全盘、PCQQ db）
     全部被判为 web 逆向候选。单轮 57 条待抓里 **23 条是这类**。
   - 为什么难防：**标题层面几乎无法区分**「某网站登录密码加密分析」与「Golang 加解密库教程」，
     二者都含 `加密/解密`。⇒ 只能靠**抓正文复核**兜底（成本 = 每轮多抓几十条）。
   - ⇒ 缓解手段（按性价比排序）：
     1. `NOTWEB` 补 `PHP|Golang|python实现|C\+\+|易语言|VB\.NET|Spring|Kaptcha|文件内容|全盘|数据库解密|内存加解密|密钥内存`；
     2. `STRONG` 的 `解密` 分支加**共现约束**（`(前端|web|js|接口|参数|登录|请求|响应).{0,8}解密`）；
     3. 抓取后**逐条看正文首段**再决定删/留，删除的 ID 记入下一轮 `BLOCK_EXTRA<N>`。

20. **「隐称」是独立于站名/宽泛词之外的一层词形，历轮最容易整层遗漏**（第九轮最大收获）：
   - 论坛帖标题常用**单字隐称**规避检索：`某音`（抖音）、`某书`（小红书）、`某东`（京东）、

24. **`content` 有三种「拿不到正文」的状态，必须分开记账，不能都当失败/空帖**（第十一轮实测）：
   - ① **反爬页**：正文含 `访问验证` / `环境检查` / `waf_*_verify` → 视为失败并重试（坑 4/13）。
   - ② **空正文**：`len(md) < 120` 或剥标题/引用后 `len(body) < 200` → 作者删正文，长期稳定。
   - ③ **权限受限**（**最易被误记**）：`RPC API Error [Code -1]: 抱歉，本帖要求阅读权限高于 N 才能浏览`。
     受限帖**既不是非目标、也不是空帖、也不该反复重试** —— 它只是当前账号权限不够。
   - 第十一轮实测 6 条受限帖（权限 >20/>30/>40），其中 2 条（`1985832`、`1831357`）**被历轮误记为
     「长期空帖」长达 4 轮**，直到本轮把返回体打印出来才发现。
   - ⇒ 抓取脚本必须用 `PERM_RE = r"阅读权限高于\s*(\d+)|抱歉，本帖要求"` 单独分流，
     并在 README 里单列一张「空正文 / 权限受限」表；**受限清单是「下次可捞」清单，不要拉黑**。
   - 注意：探针脚本（`probe*.py`）若只按 `len(md) > 200` 判成功，会把受限帖静默写成 0B 文件 ——
     复核时要单独看 0B 条目并手工执行一次 `hubcli <platform> content --url <id>` 看原始错误。

25. **WAF 页从「滑块」换成「文字验证码」时，`navigate` / `reload` 都可能无效 —— 关掉标签页新开一个**（第十一轮实测）：
   - 症状：`search` / `Thread` 静默返回 `[]`，`hubcli list` 里该平台执行器**消失**（`Code 3001 no client available`），
     标签页标题变成 **`访问验证`**（`waf_text_verify.html`）。
   - 与坑 22 的滑块页不同：这里的 `screenshot` **第一次能返回 dataURL，随后全部 30s 超时**（反调试逐步生效）；
     `navigate` 回首页 + `reload` 都**无法**让执行器重新注册（坑 22 的方法在此失效）。
   - **有效恢复**：
     ```bash
     hubcli browser open --url "https://www.52pojie.cn/"   # 新开一个干净标签页
     hubcli browser close --tab_id <旧WAF标签页id>          # 关掉被污染的页
     hubcli list                                            # 执行器回来了
     ```
   - 恢复后**必须删掉 WAF 期间误落的 `search*/` 结果文件**（那些 `[]` 会被当成「真实零结果」落盘，
     下一轮 resume 时会跳过它们 → 整批关键词永久静默丢失）。这是坑 13 的加强版。

26. **两个「组合词」维度是本技能当前最高产的召回手段（第十一轮实测 73 词 → 14 篇存量老帖）**：
   - **`视频 / m3u8 / 直播 / 影视 / widevine / h5e / 直播源` × `解密 / 解析`** —— 一次捞回 9 篇，
     且这些标题**几乎不含任何 `STRONG` token**（`央视 h5e 视频解密脚本`、`某浪m3u8解密简单分析`、
     `HTML5视频解密的方法（widevine的破解思路）`、`斗鱼直播真实地址解析` …），历轮口径**完全看不见**。
   - **`平台 / 网站 / 系统 / 网页` × `登录 / 接口`**（**无算法词**的标题）—— 补回
     `逆向分析青果教务系统的登录接口`、`【JS逆向学习实践】某招标网站登录X-Sign逆向` 等。
   - 反之，**`爬虫/采集/抓包` × `加密/签名/参数` 这个组合实测全零**（12 个词 0 条），
     `加密入口 / 加密断点 / 参数定位 / js扣取 / webpack扣` 等「动作工程词」也**全部零结果** ——
     说明动作词在标题层已被写尽，不要再投入预算。

27. **`hubcli <platform> search --keyword <中文>` 会因「字符集不匹配」**恒定返回 `[]`** —— 这是历轮「假零」的真正来源之一**（第十二轮实测，单轮因此多召回 88 篇）：
   - 现象：任意中文关键词都返回 `[]`（连 `京东`、`滑块` 这种热门词也是），**不报错**，与坑 3「真实零结果」、
     坑 13/17「WAF 静默」完全无法区分。历轮把这当成「关键词已穷尽」，其实整层搜索能力已经失效。
   - 原因：hubcli 把关键词按 **UTF-8** 百分号编码提交，而 52pojie 是 **GBK** 站点，服务端按 GBK 解码 →
     关键词变乱码（`滑块` → `婊戝潡`）→ 搜索页明写 `结果: 找到 “婊戝潡” 相关内容 0 个`。
   - **验证方式**：直接 `browser navigate` 到
     `search.php?mod=forum&srchtxt=<UTF-8 编码>`，看页面把关键词解成什么；再换 GBK 编码对比。
   - **修复（实测一条命令即恢复）**：绕开 `search` 命令，自己驱动浏览器：
     ```bash
     # 滑块 的 GBK 百分号编码 = %BB%AC%BF%E9
     hubcli browser navigate --tab_id <tab> --url        "https://www.52pojie.cn/search.php?mod=forum&srchtxt=%BB%AC%BF%E9&searchsubmit=yes"
     ```
     现成脚本：`scripts/browser-search.py --kw-file kw.txt --outdir search<N> --tab <tab>`（含断点续跑、
     自动翻页、限频重试、WAF 中断）。
28. **`subprocess.run(..., shell=True)` 在 cmd.exe 宿主下会把 URL 里的 `&` 当命令分隔符**（同轮实测）：
   - 表现：`browser navigate` 的 URL 被截断成 `search.php?mod=forum`（`&srchtxt=...` 整段丢失），
     搜索页返回的是**没有关键词的表单页**，解析出来 0 条 —— 看起来像「搜不到」。
   - hubcli 是 `.EXE`，**直接 `shell=False` 传参数组**即可（不要用 `shell=True` + 引号绕）。
     历史脚本里 `shell=True` 能用是因为 `content --url <纯数字>` 这种参数没有 `&`。
29. **不能拿 `waf_slider_verify` / `waf_text_verify` 之类的字符串直接判 WAF**（同轮实测，最浪费时间的误判）：
   - 正常的搜索结果页尾部 `<script>` **就引用了** `waf_*_verify.html`（WAF 的前端探针），
     于是「页面含 `waf_slider_verify`」对**每一页**都成立 → 扫描在第一个关键词就「熔断」。
   - 正确判据：**先看页面有没有搜索结果标记**（Discuz 是 `相关内容` / `<li class="pbw"`），
     **没有标记** 且命中 WAF 文案（`访问验证` / `请完成安全验证` / `向右滑动填充拼图`）才判 WAF。
   - 同理，「真实零结果」页也含 `相关内容 0 个` → **有标记**，必须与 WAF 页区分开，否则会把真零也判成 WAF。
30. **落盘语料可能是「部分乱码」——头部元信息正常、正文整段是西里尔字母串**（B13 实测，直接毁掉两篇高价值文章的可用性）：
   - 现象：同一文件里，52pojie 的 `> **作者** / **版块** / **原文**` 全正常，但正文是
     `дёҖгҖҒеҲҶжһҗ` 这种串（如某篇很小众的「网站 js逆向与 m3u8 解密」）。
     正文**整篇不可读**，等于该文章从未被归档。
   - 成因：正文那段先被按**单字节西里尔码页**解码成字符串、再整体按 UTF-8 写盘。
   - 🔴 **不可以用「整文件选一种编码」去救**（会把正常的中文头一起毁掉，且**不报错**）。
     必须**逐行**处理，且只处理"含成串西里尔字母"的行。
   - 🔴 **码页不止一个**：实测出现过 **`ptcp154`（Cyrillic-Asian，CP154）** 与 `cp1251`；
     两者在 `0xC0–0xFF` 完全一致、`0x80–0xBF` 不同。用错码页时**一半的行照样能编出"合法 UTF-8"**，
     于是静默产出错字（实测 `分析`→`倆析`、`师傅`→`帀傅`）。
     **判据：`分析`/`师傅` 这类高频词被还原成生僻字 ⇒ 码页选错了。**
     更硬的办法是**判优**：用 GB2312 当"常用字基准"，取越界字符最少的那套还原。
   - 🔴 **同一行里可能混用多张表**：实测同一行同时出现 `ptcp154` 字符、**CP1252**（`‘` = 0x91）
     与 **Latin-1**（`»` = 0xBB）。⇒ 正确做法是"**逐字符求候选字节、用整段必须是合法 UTF-8 收敛**"，
     而不是选一个码页。
   - **现成工具**：`scripts/repair-encoding.py`
     ```bash
     python scripts/repair-encoding.py --scan <语料目录>            # 只报告，不改动
     python scripts/repair-encoding.py --fix  <语料目录>            # 就地修复，自动留 .bak-encoding
     ```
     内含 `--selftest`（**项数以实跑输出为准**，不要手抄进文档），覆盖：两种码页的还原、**混表行还原**、错码页必须被判掉、
     干净文本逐字节不变、幂等（修完再跑不变）、**中英混排行默认拒绝执行**、截断字节兜底、合法西里尔文本不被误改。
   - 边界：行末 UTF-8 字节真的丢了（数据截断）时，工具只还原**最长可解前缀**、残缺尾巴原样保留 ——
     **数据丢失推不回来，工具不猜**。
   - ⚠️ **每次跑完抓取/归档后都应做一次 `--scan`**：这类缺陷**不影响任何统计口径**
     （文件数、唯一 ID、空文件数全都正常），只有打开正文才看得出来。

## 反模式

31. **「全量分页复扫」的边际收益会在中途归零 —— 应该边扫边探针，不要盲等全量跑完**（第十三轮实测，本类任务最重要的效率结论）：
   - 背景：把历轮累计的几百个历史关键词逐个用浏览器全量分页重扫（坑 27 的修复），
     单关键词约 15–20 s（受 `搜索限频 10 秒` 硬约束，**不能并发、不能压缩 GAP**），586 个词要 **2.5–3 h**。
   - 现象：按优先级（旧工具命中 ≥38 必被 `--limit 40` 截断的词优先，再按旧命中降序）排序后，
     **高价值词全部集中在最前面**；本次第 293→470 词（177 个词）候选池**零增长**
     （池 17537 条不变、待抓量还略降），尾部基本是长尾品牌词且多为真实零结果。
   - **正确做法 = 中途探针**：每扫完 ~50 个词，就跑一次「合并当前 `search<N>/*.json` → 过一遍口径
     → 数候选/待抓」，一旦**连续 2 个探针区间零增长**（或 <3 篇新增）就**收口**，不必跑满。
     探针脚本只读本地文件，**不会与扫描并发**（这点很重要，见坑 17）。
   - 本轮收益：470/586 收口，省下 ~1.5 h，实际未损失任何候选。
   - ⚠️ 收口后 `search<N>_pool.json` **可能是旧的**（脚本只在每 10 词 / 末尾落盘，被 kill 时最后一批没写）
     → **必须先从 `search<N>/*.json` 重建池**（逐个 json 合并去重）再喂给 merge 脚本，否则会漏掉最后几十个词的结果。
   - ⚠️ 长任务用工具的 `run_in_background`（坑 8）；停止用 `TaskStop`（不是 kill 进程，避免连坐）。

32. **「全量分页复扫」会成批涌入两类新噪声，必须前置黑名单**（第十三轮新增第 32 条，与坑 19 同型但类别不同）：
   - 因为 `--limit 40` 截断被历史漏掉的，除了高价值老帖，还有整类**低价值但标题含算法词**的老帖：
     - ① **native 反调试 / OD / IDA / 加壳**（几乎全在『脱壳破解区』）：标题含「反调试 / 加壳 / VMP / 混淆」，
       正文是 x64dbg/OD/IDA 的 PE 层分析 —— 与 web 无关。本轮 22 条。
     - ② **验证码「识别」工具/源码**（不是「验证码逆向」）：标题含「验证码识别 / 识别模块 / 识别源码」，
       正文是 OCR/易语言源码/生成器 —— 属图像识别，非逆向。本轮 19 条。
   - **判据**：`识别` vs `逆向`、`脱壳/加壳/OD/IDA/PE/驱动` vs `浏览器/接口/参数/前端`。
     这两类的**误收率接近 100%**，应直接进 `BLOCK_EXTRA<N>`，不要浪费抓取预算逐条抓正文。
   - 本轮同时确认：**真阳性仍然只集中在两类**——`视频/m3u8/直播源解密` 与 `登录/接口/签名/参数逆向`
     （各 14 篇，占新增 37 篇的 76%）。

33. **给 `README.md` 追加分节时，不要用 shell 的 `{ echo ...; cat file; } >> README.md`**（第十三轮实测踩坑）：
   - 现象：`cat` 的相对路径写错（在 `docs/references/` 下 cat 了 `artifacts/` 里的文件）时，
     `cat` 报错但 **`echo` 的引言已先追加进去**，README 里留下一段**只有标题没有表格**的残节；
     而且 `&&` 链条后面的统计命令仍会「成功」，第一眼看不出来。
   - 正确做法：**用 Python 脚本**一次读完「引言 + 分节文件」再整体写盘；回滚用
     `n=$(grep -n "^## 十X" README.md | cut -d: -f1); sed -i "$((n-1)),\$d" README.md`。
   - 追加后**必查**：`grep -c "^## "` 的节数 + 尾部 3 行 + 头部计数与终检块是否已同步。
