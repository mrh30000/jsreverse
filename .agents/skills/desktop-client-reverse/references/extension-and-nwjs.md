# 打包型前端的另外三种壳：浏览器扩展 / nw.js / Electron 埋点法

本文件是 `desktop-client-reverse` 的**第四类壳**（前三类：Electron / WebView2 / JSC 字节码）。
共同点：**前端被装进一个"壳"里分发**，所以打法与 Electron 一致 —— 先解包、再定位、改判断或加埋点、重打包。

**一句话结论**：拦住你的通常**不是加密，而是校验与加载顺序**。
"解包成功但跑不起来 / 改完没反应"几乎都出在这两处，而不是出在"读不懂代码"。

---

## §1 浏览器扩展（CRX / 解压目录）

### §1.1 先找到目录（推荐顺序）

| 顺序 | 做法 | 说明 |
| --- | --- | --- |
| 1 | `chrome://extensions/` → 看 **扩展 ID** | 只用看首尾几位就能在一堆目录里认出它 |
| 2 | `chrome://version` → **个人资料路径** | 打开该路径下的 `Extensions/<ID>/<版本号>/` |
| 3 | 有些浏览器/来源能直接下到 `.crx` | `.crx` 本质是带签名的压缩包，改后缀为 `.zip` 即可解 |

**两个坑**：

1. `Extensions/<ID>/` 下面那层**版本号文件夹**才是真正的插件目录，别拷错一层；
2. Chrome 74+ **禁止离线安装未认证插件** ⇒ 必须打开右上角**开发者模式**，再"加载已解压的扩展程序"；
   想彻底去掉"不安全扩展"提示，得动 `version.dll` 这类浏览器补丁（等价物：改走 Chromium 分支或策略安装）。

### §1.2 关键词定位的固定套路（这一族最高效的一步）

1. 从**界面文案**入手（不是从代码入手）。例如弹窗里那句
   `Your trial period expired` / `试用会员还剩多长时间过期`；
2. 在**整个插件目录**里搜索该文案（编辑器"在文件夹中查找"，`notepad++` / `sublime` 都支持）；
3. 命中的通常是**语言文件**（`_locales/*/messages.json`）⇒ 拿到**变量名**（如 `trial_expired` / `remained`）；
4. 再用**变量名**全局搜索 ⇒ 这次命中就是**逻辑文件**。
   实测命中面：`background.js` / `options.js` / `prefs.js` / `content.js`。

> 关键顺序：**文案 → 语言文件 → 变量名 → 逻辑文件**。
> 直接从代码里翻（尤其压缩过的）会慢一个数量级；作者把文案和逻辑分开写，等于给了你一个免费的符号表。

### §1.3 三种会员/许可校验形态与改法

| 形态 | 特征 | 改法 |
| --- | --- | --- |
| **状态机枚举** | `this._state === t.SUBSCRIPTION_OK` / `SUBSCRIPTION_EXPIRED` / `TRIAL_EXPIRED`；由一个 `_verifySubscription()` 统一赋值 | 把"成功分支"的赋值**提到判断之外**，或把条件改 `true`。**优先选改动最小的那一种** |
| **令牌解码** | `_decodeTokenPayload(token)` → `{expiredAt, subscriptionStatus, trialDays, createdAt}`；随后 `Date.now() < e` | 改时间判断；或让解码结果固定 |
| **许可证校验函数** | `verifyAndSaveLicens()` 里"第一个 `if` = 验证通过"、"其余 `if` = 试用/过期" | 把第一个 `if` 的**内容搬到 `if` 之外**，其余分支注释掉 |

三条经验：

1. **少改动**优先：能改一个常量就不要改结构（改结构容易连带坏掉别的功能）；
2. 找到判断后**往上溯源赋值点**：`this._state` 被多处赋值 ⇒ 要改的是**赋值处**，不是消费处；
3. "把 `支付失败` 的字符串改成 `支付成功` 就好了"是**错的** —— 字符串不影响控制流，原文作者明确吐槽过这一点。

### §1.4 三个调试面（扩展的"三块屏"）

| 面 | 怎么开 | 适用 |
| --- | --- | --- |
| **popup** | 在扩展图标上**右键 → 审查弹出窗口** → Sources 格式化 → 下断点 → `location.reload(true)` | 点图标才出现的界面 |
| **content script** | DevTools → **Sources → Content Scripts → 选对应站点（有 iframe 就选对子帧）→ 选扩展名** | 注入到页面里的逻辑 |
| **background / service worker** | 扩展详情页 → "检查视图（service worker）" | 网络请求与全局状态 |

**一个高价值技巧**：Sources 面板的 **"异常处暂停"** ——
在"未被捕获的异常"处断下时，**调用栈、局部变量、报错信息都在**，
比"猜哪里出错再埋点"快得多（尤其代码被压缩时）。

⚠️ **MV2 → MV3 的差异先确认**：MV3 的 background 是 **service worker**（无常驻、无 DOM），
`declarativeNetRequest` 取代 `webRequest` 阻塞式改写，权限拆成 `host_permissions`。
在 MV3 里按 MV2 的断点位置找，会找不到。

### §1.5 重打包与"身份"

- `打包扩展程序` + **私钥（`.pem`）**；私钥 = **插件身份**（类似 Android 签名）；
- ⚠️ **不同插件用同一私钥会互相覆盖**（原文作者的惨痛教训）；
- 分享 `.zip` 解压版时，**先打包再改后缀**：带着 `key` 系统才认为这是"同一个插件在更新"，
  否则会出现**新旧版本共存**、设置要手工迁移；
- 改 `manifest.json` 的 **`update_url` 与 `version`** 是常规收尾（避免自动更新覆盖你的修改）；
- **勤备份**（原文三个"注意！"说的就是这件事）。改坏了要么撤销到不报错为止，要么回退备份。

## §1.6 另一条用途：扩展的「能力面」——请求头改写与门禁绕过三法

§1.1–§1.5 讲的是**读扩展**（改它的许可证判断）。反过来，扩展本身也是一种**改页面行为的手段**：
它跑在浏览器 API 层，能改的东西是网页 JS **改不了**的 —— 请求头、Cookie 策略、跨域设置。

**三法分档（副作用从小到大）**：

| 档 | 做法 | 为什么有效 | 代价 |
| --- | --- | --- | --- |
| ① 伪装来源站 | 在 `onBeforeSendHeaders` 里**删掉** `Referer` 再 `push` 一个三方站（如 `https://t.co/`） | 站点把「从社交平台点进来」判为潜在新用户，不收门禁 | 最小；登录/点赞/评论照常 |
| ② 伪装搜索引擎爬虫 | 删掉 `User-Agent` 与 `X-Forwarded-For`，换成 `Googlebot/2.1` UA + `X-Forwarded-For: 66.249.66.1` | 站点要靠 SEO 流量，**不会**拦广告机器人 | 稍大；站点若做 UA 风控会露馅 |
| ③ 禁用该站全部 Cookie | `chrome.contentSettings.cookies.set({primaryPattern: <站点>, setting: 'block'})` | 「每天免费 N 篇」类限额靠 Cookie 计数，禁掉就永远像第一次访问 | 最大：**登不了录、点不了赞** |

**工程形态**：

- 头改写走 `chrome.webRequest.onBeforeSendHeaders`：`details.requestHeaders.filter(h => h.name !== 'Referer')`
  **再** `push` 新头，最后 `return {requestHeaders: details.requestHeaders}`。
  ⚠️ 必须「先过滤再 push」——只 push 不过滤会**留下两个同名头**，服务端取哪个不确定。
- 三种方法各自有一个**按站点开关的白名单字典**（源文里是 `paywallSMWhitelistDict` /
  `paywallSpoofWhitelistDict` / `paywallCookieWhitelistDict`）。
  ⇒ 判据：**三法是「按站点选一」，不是叠加**（源文明确「并不是所有的网站都需要使用上述 3 种方法」）。

**坑**：

1. **③ 改的是浏览器持久设置**，不是这次请求的临时头 —— 调试完必须还原，否则症状是
   「昨天还能登录，今天莫名掉登录 / 点赞按钮点了没反应」，而你会去别处找原因。
2. ② 的伪装**要成对改**：只换 UA 不换 `X-Forwarded-For`，站点按出口 IP 判定爬虫就穿帮。
3. 这一族**在 `Dist` 目录里就能看到全部逻辑**（`bg_scripts/.../paywall_bypass.js`），
   不需要脱壳、不需要调试器 —— 与 §1.2 的「关键词定位四步」是同一套动作。
4. **边界**：这类"绕过门禁"只适用于**自己有权访问的内容**；源文自己也在开头放免责声明。
   把它当技术理解（请求头/浏览器设置能被谁改），不要当推荐做法。

## §2 nw.js（`nwjc` 二进制加密）

### §2.1 判据

| 现象 | 判断 |
| --- | --- |
| `index.html` 里有一个全局环境标记（如 `is_nwjc`） | **nw.js + `nwjc` 二进制加密** |
| 加载一个 `*.min.bin`（而不是 `*.js`），并**定时判断是否加载完成** | 同上 |
| 目录里同时有 `x.js`、`x.min.js`、`x.min.bin` | `x.min.bin` 很可能是 `x.min.js` 经 `nwjc` 编译后的产物（**体积量级相近**） |
| 用 `nw.exe` / `nwjc` 相关文件做启动器 | 同上 |

`nwjc` 是 nw.js 官方的"源码保护"：把 JS **编译成二进制**再加载（官方文档在 nwjs.io 的
"Protect JavaScript Source Code"）。**它不是加密，是编译** —— 所以不要指望"解密"。

### §2.2 三条路（按推荐顺序）

1. **换回源码**（最快）：把加载 `*.min.bin` 的那段导入代码**删掉**，改成引入打包前的 `x.js` / `x.min.js`。
   能跑起来就说明**它就是同一份源码**，后面所有分析都在明文 JS 上做。
2. **关开关 + 开 debug**：把 `nwjc` / `nwjs` 开关关掉并打开 `debug` 开关。
   ⚠️ **这一招通常不够** —— 因为真正拦住你的是**文件校验**（见 §2.3）。
3. 读二进制：最后才考虑（本技能不提供 `nwjc` 反编译；能用前两条路就不要走这条）。

### §2.3 拦路虎是"文件校验"，不是"加密"

原文实测：换回源码后**打开游戏直接闪退**，原因是那段 `MD5 摘要校验`。

> **MD5 不是加密**（原文作者连强调三遍）。它只做"完整性判断"，
> 而"能不能过"取决于**你怎么改那个判断**，与"能不能算出 MD5"无关。

处置：把校验判断改成 `false` 绕过；**同时别忘了把"加载完成"的检测放回来**
（原文的一次黑屏就是只绕过校验、没恢复加载完成检测）。
若还有"购买检测"（steam 之类），一并去掉。

### §2.4 资源解密：先找调用点，再谈算法

游戏/客户端里的图片常以"文件名 = MD5 摘要"的形式存盘，内容经过
**MD5 摘要 + XOR + 截取**的组合变换（`decryptImg` 一类函数）。

**不要逐步逆这个算法**。正确做法：

1. 搜 `img` / `decrypt` 关键词定位到解密函数；
2. 搜"**谁调用了它**" —— 找到调用点（往往是"打开某个界面时解密"）；
3. **新建一个输出目录**，把调用点的循环改一下（顺便把相对路径补上），
   直接**跑一遍**批量导出明文资源。

> 判据：**能跑就不要逆**。这是"有源码可跑"场景下的通用效率原则。
> 反例：如果对方**删了调用代码**怎么办 —— 原文口径："他删文件，那你就删文件夹呗"，
> 即从产物形态反推（文件命名即摘要、目录即分类）。

## §3 Electron 的"埋点法"（代码压缩、断点不方便时的兜底）

### §3.1 什么时候用

- `asar` 解包后代码是**压缩成一两行**的；
- **格式化之后代码"变红"（语法被美化器拆坏）⇒ 重新打包跑不起来**；
- 断点打不准（不知道在哪），或者调试器一开程序行为就变。

### §3.2 做法（顺序法，而不是二分法）

1. 在**疑似位置**插入一组可区分的标记：

   ```js
   console.log("1");
   console.log("2");
   console.log("3");
   console.log("4");
   ```

2. **重新打包替换**回 `app.asar`，跑程序看输出到了哪一号；
3. 用 **Debugtron**（或等价的"强制开调试"工具）让 Electron 进程**开 DevTools**，
   才能看到 console 输出；
4. 反复收窄，直到定位到那几行关键代码；
5. 把关键代码**扣出来**单独跑。

> **为什么用顺序法而不是二分法**：压缩代码里"半段函数"没有语法意义，二分容易切出跑不起来的产物；
> 顺序插桩每次只改一处、永远可回退。

### §3.3 扣出来结果不对时的第一反应

原文实测：扣出的代码跑出来**结果不对** ⇒ 排查后发现**还执行了一次 base64**。

⇒ **判据**：扣出来不对，**先怀疑"还有一层编码/还有一次调用"，不要先怀疑"扣错了"**。
两条排查动作：① 在扣出点前后各加一个 `console.log` 看**实际入参出参**；
② 搜同一个函数名/同一段逻辑是否在别处**又被调用了一次**。

## §4 三类壳的共性（可以背下来）

| 阶段 | 动作 | 常见拦路虎 |
| --- | --- | --- |
| 1 定壳 | 有没有 `manifest.json`（扩展）/ `is_nwjc`（nw.js）/ `app.asar`（Electron） | 把"打包"当成"加密" |
| 2 拿到可读源码 | 解包 / 换回源码 / 抠函数 | 偏移错位、`nwjc` 编译、压缩成一行的代码 |
| 3 定位 | 文案 → 变量名 → 逻辑文件（扩展）；`img`/`decrypt` 关键词（nw.js）；console.log 顺序埋点（Electron） | 从压缩代码硬读 |
| 4 改 | 改**判断**（不是改字符串）；改**赋值处**（不是消费处） | 文件/完整性校验、购买校验 |
| 5 跑起来 | 恢复被自己关掉的检测（加载完成检测）；重打包；切 debug 开关 | 只绕过校验没恢复检测 ⇒ 黑屏 |
| 6 验证 | 目标功能可用 + 副作用可接受 | 改了字符串就以为解锁了 |

**六条跨壳通用纪律**：

1. **改判断，不改字符串**；
2. **改赋值处，不改消费处**；
3. **绕过校验之后，记得把"加载完成/初始化"的检测恢复**；
4. **每次改动前备份**（原文三个"注意！"+ 一个新旧版本共存的教训）；
5. **能跑就不要逆**；
6. **解包成功 ≠ 拿到逻辑** —— 先跑通，再读代码。
